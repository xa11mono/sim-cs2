# Ресурсы и карты: как хранить и загружать (v598, 24.11.2026)

Основа — измерения из `HTML_SIZE_AUDIT.md` и `LOADING_PERFORMANCE.md`. Ни одно предложение здесь не меняет числа
геометрии, навигации, видимости или физики: меняется только упаковка и момент загрузки.

## 1. Как устроено сейчас

Всё лежит **внутри одной страницы**:

| ресурс | где | формат | размер (Ancient / Mirage) |
|---|---|---|---|
| движок и интерфейс | `<script>` | JS (минифицирован) | 1 979 206 / 1 979 205 Б |
| геометрия | `MAP.map3d` | base64 → zlib | 9 815 408 / 2 089 364 Б (распаковано 39,5 / 29,3 МБ) |
| навмеш, зоны | `MAP.navmesh`, `MAP.zones` | JSON-текст | 279 135 / 488 583 Б |
| высоты, укрытия, стены, прострелы | `MAP.heights/cover/walls/wallbang` | JSON-текст | 85 067 / 185 388 Б |
| тактики, про, лайнапы, броски | `MAP.*` | JSON-текст | 1 148 291 / 1 337 951 Б |
| радар | `MAP.radar` | PNG → base64 | 63 894 / 140 607 Б (текст 85 225 / 187 509 Б) |
| звуки | `SND_DATA` | MP3 → base64 | 1 279 395 Б (текст 1 705 860 Б) |
| шрифты | CSS `@font-face` | WOFF2 → base64 | 356 415 Б (текст 475 220 Б) |
| фото HUD | `640_scoreboard_players.js` и др. | PNG → base64 | 427 518 Б (13 фото) |

Данные карты вставляются текстом (`src/mapset.py`), без перекодирования — числа остаются ровно как записаны
(включая `-0`). Геометрия распаковывается при первом вопросе `m3()` (на загрузке — из `computeZoneDanger`).

## 2. Один общий движок для всех карт

**Сейчас:** исходник один, но каждая страница несёт копию движка (2,04 МБ без сжатия пробелов; отличие — название
карты). Проверено побайтово (`engine_dupe.js`).

**Возможно:** вынести движок в отдельный файл `engine.js`, карту — в `maps/<id>.map` + манифест. Страница тогда —
тонкая оболочка (`index.html` + `engine.js` + `maps/*`). Никаких изменений в логике: `MAP` подставляется в то же
место (`var MAP = …` заменяется на загрузку и передачу объекта), но загрузка становится асинхронной — на это нужно
согласие владельца, потому что меняется поведение «открыл файл — сразу играет».

**Что даёт (по байтам):**

| | сейчас | общий движок + внешняя карта |
|---|---:|---:|
| первая загрузка Ancient | 15,83 МБ | 15,83 МБ (движок 2,08 + звуки 1,71 + шрифты/CSS 0,61 + карта 11,41 + радар) |
| вторая карта в том же браузере | +9,43 МБ | +5,01 МБ (только данные Mirage) |
| повторная загрузка той же карты | 9,43–15,83 МБ заново | только проверка версии (манифест) или ничего при `immutable`-кэше |

Т.е. выигрыш не на первой загрузке, а на **второй карте и повторных загрузках**; при 7 картах экономия — 6 × 4,35 МБ
общих копий.

## 3. Независимые пакеты карт

Пакет карты = `data/maps/<карта>/` в одном контейнере:

```
maps/ancient.map        (бинарный контейнер: заголовок, оглавление, блоки)
  ├─ meta.json          id, name, store, db, pxUnits, zoneLayer, ui, spawns
  ├─ geometry.bin       map3d: prims/sight/nade/floors/sky (zlib-блоки как есть)
  ├─ nav.bin            navmesh.areas + zones.zonemap (плоские массивы)
  ├─ gameplay.json      tactics, pro, ctspots, postplant, lineups, nadelanes, nadeguess…
  └─ radar.png          картинка
```

- Пакет версионируется целиком: `sha256` в манифесте; игра проверяет и кэширует по хэшу.
- Пакет не содержит кода — новая карта не копирует движок.
- Формат контейнера — тривиальный (8-байтовый заголовок + таблица блоков + выравнивание), чтобы Rust и TS читали
  одно и то же без библиотек.

Оценка размера пакета (без переупаковки, только снятие base64): Ancient ≈ 7,36 МБ геометрии + ~1,5 МБ JSON + 64 КБ
радара ≈ **8,9 МБ** вместо 11,4 МБ в странице; Mirage ≈ 1,57 МБ + 1,6 МБ + 141 КБ ≈ **3,3 МБ** вместо 5,0 МБ.

## 4. Отложенная загрузка ресурсов отрисовки

Что можно грузить **после первого кадра** без влияния на симуляцию:

| ресурс | сейчас грузится | можно | риск |
|---|---|---|---|
| звуки (1,71 МБ) | литерал при разборе | внешний файл по первому жесту (уже декодируются по кнопке) | первый звук может опоздать на кадр — проверить `sndInit` |
| фото HUD (0,43 МБ) | литерал | `fetch` после первого кадра, показывать инициалы до загрузки | вид панелей на старте изменится — согласовать |
| радар (0,06–0,19 МБ) | data URI до первого кадра | оставить как есть: нужен сразу (фон) | — |
| шрифты (0,48 МБ текста) | CSS до отрисовки | внешний файл + `font-display: swap` | мигание шрифта — согласовать |
| редакторы/демо (≈0,25 МБ JS) | всегда | отдельный бандл по кнопке | кнопки редактора появляются с задержкой |

Звуки и фото — самые безопасные кандидаты: они не участвуют в расчёте раунда (`sndInit` вызывается по жесту;
фото — только DOM). Шрифты и редакторы затрагивают вид/удобство — это решения владельца.

## 5. Визуальная геометрия отдельно от геометрии симуляции

Уже разделено по данным:

- `walls.json` — стены радара, используются **только для рисования** (`applyWalls`, редактор);
- `MAP.map3d` (`prims`, `sight`, `floors`) — видимость, «в стене», пули, гранаты, пол;
- `navmesh.json` — граф хода;
- `heights.json`, `cover.json` — высоты и укрытия для решений.

Но в странице они лежат рядом и распаковываются вместе. Предложение: в пакете карты держать `geometry.bin`
(симуляция) и `visual.json`/`walls` отдельно, чтобы 3D-вид и редактор могли грузить визуальное позже. Точность
не меняется: это те же числа.

## 6. Совместное использование неизменяемых данных между матчами

- Внутри одной сессии `MAP` уже неизменяем: `freshMatch` не пересобирает карту, навмеш строится один раз.
- Между вкладками/страницами данные сейчас не разделяются (каждая страница — своя копия).
- При общем движке и пакетах: браузерный кэш (`Cache-Control: immutable` + хэш в имени) отдаёт пакет один раз;
  в памяти одной вкладки пакет можно держать в `ArrayBuffer` и пересоздавать производные структуры
  (`m3Load` → типизированные массивы) при смене карты, не перезагружая страницу (вариант C).

## 7. Кэширование ресурсов

- Сейчас: комментарии вырезаны, но **нет ни хэшей, ни версий в именах**; страница целиком — один артефакт.
- Предложение: `engine.<hash>.js`, `maps/<id>.<hash>.map`, `sounds.<hash>.json`; `Cache-Control: public, max-age=31536000,
  immutable`. Тогда повторный запуск — 0 байт по сети, только проверка манифеста (несколько КБ).
- Локальные отметки уже хранятся по ключу `store` карты (`map.json`), это надо сохранить при любом варианте.

## 8. Компактные бинарные форматы — что подтверждают измерения

| данные | сейчас | бинарный эквивалент | выигрыш |
|---|---:|---:|---:|
| `map3d` (Ancient) | 9 815 408 Б base64 | 7 361 558 Б zlib (без base64) | −2,45 МБ (−25 % поля, −15,5 % страницы) |
| `map3d` (Mirage) | 2 089 364 Б | 1 567 023 Б | −0,52 МБ |
| навмеш (Mirage) | 400 124 Б JSON | ≈ 4 байта × координата + заголовок; ориентировочно 100–150 КБ | −0,25…0,3 МБ |
| звуки | 1 705 860 Б base64 | 1 279 395 Б MP3 | −0,43 МБ |
| фото | 570 024 Б base64 | 427 518 Б PNG | −0,14 МБ |
| шрифты | 475 220 Б base64 | 356 415 Б WOFF2 | −0,12 МБ |

Плюс к байтам: снятие `atob` (в профиле старта Ancient `atob` + `dec` ≈ 110 мс из 1,8 с профиля) и меньше пиков
памяти при распаковке (base64-строка + бинарная копия живут одновременно).

**Где бинарный формат не нужен:** `tactics`, `pro`, `lineups`, `nadelanes` — их читают глазами и правят руками;
JSON с комментариями (`_about`) ценнее нескольких сотен килобайт. Решение — по замеру: если поле < 100 КБ и
редактируется человеком, оставить JSON.

## 9. Добавление карты без копирования движка

Сейчас: `mkpub.py --map X` даёт страницу с копией движка. При варианте B/C: `map_build.py X` → пакет `X.map`,
положить в `maps/`, добавить строку в `maps/index.json` — движок тот же, страница та же. Это и есть цель
«добавить карту без копирования движка»; данные при этом собираются тем же `map_build.py`.

## 10. Ограничения и что нельзя трогать

- Не менять точность: координаты, навмеш, высоты, укрытия, прострелы, видимость и физика — бит в бит.
  Любая переупаковка проверяется сверкой (лучи/броски/маршруты), как в `bench/stage3` (1200 лучей, 900 ходов,
  48 бросков, 400 маршрутов — суммы совпали).
- Не делать загрузку асинхронной без решения владельца: сейчас игра готова к первому кадру сразу после разбора
  скрипта; внешние файлы добавят задержку загрузки (локально — единицы миллисекунд, по сети — зависит).
- Не выносить `MAP` в `fetch` «на всякий случай»: на загрузке `MAP` нужен синхронно (`var MAP` в 010, `applyWalls`
  в 030, `computeZoneDanger` в 060). Нужен либо блокирующий загрузчик (XHR sync — плохо), либо рефакторинг
  инициализации в `boot(map)` (это уже изменение устройства, фаза 3+).
