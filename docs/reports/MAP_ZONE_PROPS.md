# Свойства зон для тактик на любой карте — что есть и чего нет (v561, 11.11.2026)

Источник списка — ответы нейросети по тактикам T, расстановкам CT и клатчам (`docs/PRO_PLAY.md` §6з). Сейчас в наборе карты из свойств
зон есть только «вода» (`zones.json` → `props`), точки сайтов и спавнов; всё тактическое записано **списками названий зон** в
`tactics.json` (`pos.<сайт>`: ctHold, ctSecond, ctRetake, tClear, tPost, entries; розыгрыши T и расстановки CT — по названиям) — на новой
карте их пишут руками. Многое код уже считает на лету, но не хранит как свойство зоны.

| свойство | что значит | сейчас | как получить для любой карты |
|---|---|---|---|
| связность, обходы | какие зоны соединены, есть ли путь в спину | граф зон по порталам (`BZ.nbr`, 200) | есть |
| сторона карты | A / мид / B | центр мида `geoMid` руками; сайты — точки | по пути до сайтов (доля пути) — посчитать при сборке |
| входы сайта и ширина | откуда заходят на сайт, узкий / широкий | `pos.<сайт>.entries` — названия руками | соседи зон сайта по порталам + ширина портала — при сборке |
| вертикальность | этажи, сверху / снизу | навмеш по уровням, высоты, 3D-геометрия | есть |
| время T и CT от спавна | когда может быть первый | `REACH` (200) на лету | есть; сохранить как свойство |
| **время первой встречи** | кто приходит раньше: T или CT | нет | из `REACH`: зона, где T не позже CT, — ранний пик без гранаты опасен |
| время ротации | от сайта до сайта для CT и T | путь на лету (`zoneDijkstra`) | при сборке |
| **зона контроля** | за что T борются в начале | нет (в розыгрышах — названиями) | демки: доля времени T и CT в зоне на 5–25 с + где первые контакты |
| **зона сбора перед выходом** | где T ждут выхода вне прострелов | `stage` в розыгрышах — названиями | демки: где стоят ≥ 2 T за 5–10 с до входа на сайт |
| **зона лёрка** | край карты, путь ротации CT | `lurkPlans` — названиями | демки: где один T далеко от своих; граф: путь ротации CT |
| **путь ротации CT** | по чему CT ходят между сайтами | нет | граф + демки (переходы CT между сторонами) |
| откуда простреливается | число опасных направлений | `computeZoneDanger` (060) на лету | есть |
| глубина позиции | далеко ли от входа | нет | путь от входа сайта до точки |
| укрытие, путь отхода | закрыта ли, есть ли выход без линии | укрытия `cover.json`; отход — нет | укрытия есть; отход — граф + видимость |
| видит бомбу / подход к дефузу, слышит дефуз | для пост-планта и ретейка | на лету (`pickSpots` see / hideFrom; звук) | есть на лету |
| **точка сбора ретейка** | вне прострелов сайта, несколько путей | `pos.<сайт>.ctRetake` — названиями | зоны у сайта, не видимые с плант-точек, с ≥ 2 путями к сайту |
| смоки: какую линию закрывают | для выхода и «сорвалась ли граната» | лайнапы с целью; что закрывают — нет | линия «вход — опасная позиция», которую смок перекрывает |

**Предложение** (шаг 4, `docs/tasks/PLAN_TACTICS_V2.md`): свойства считает сборка карты (`tools/map_build.py` → `zones.json` `props`): из
графа и навмеша — сторона, входы, ширина, время, первая встреча, ротация, глубина, отход; из демок карты — зоны контроля, сбора, лёрка, путь
ротации CT. Код читает свойства, а не списки названий; списки в `tactics.json` остаются только как проверка (сравнить, совпало ли).
