| Ф-7 | **Состояние матча живёт вне игры:** замыкания и свойства функций (`nadeGuessStore`), «статичные» в снимке изменяемые структуры (`zoneGraph`), `newMatch` ≠ `freshMatch` | У-1, У-2, Л-9, Л-10 | проверка «на снимке» и «на ПК» показывает не ту игру, что у владельца — исправление кажется сделанным |

**Необходимые и случайные зависимости.** Необходимые: решения → знание; исполнение → навмеш/геометрия; бой → видимость; гранаты → физика и
место. Случайные (подлежат удалению): решения → `bots[]` противника напрямую; ход → `planting/defusing` (535 прерывает плант); гранаты → `_route`
(`resetNades` 420:254); 535 → `atPost`; 470/510 → `baseX`; любые → `SPOT_TEAM`; сторож → текст журнала; снимок → список переменных по `var`.

**Производительность ≠ архитектура.** Медленно: поиск пути (повторы + объекты), лучи (повторы), подбор броска (ключ). Архитектура: Ф-1…Ф-10.
Пересекаются в одном месте: П-01 (ошибка ключа кэша = фриз + логическая остановка).

## 3. Конечное устройство — слои

Поток тика: **Мир → Восприятие → Знание → Решения → Арбитраж → Исполнение → Физика/Результат → (события) → Восприятие следующего тика.**
Обратные связи сохраняются явно: исполнение возвращает **результат** (принято/отказ/выполнено/невозможно) владельцу решения; события (урон,
смерть, бросок, звук) идут в восприятие.

## 5. Что не меняется

Ситуационное мышление ботов остаётся: решения берут знание, гипотезы и цель и выдают **заявки**, а не жёсткие сценарии. Арбитраж не решает
поведение — он только сводит заявки по правилам, которые уже есть (`TASK_LEVEL`, `LOOK_LEVEL`), и возвращает результат. Механики M00…M146
переносятся вместе с их кодом; переписывание по памяти не допускается (`MIGRATION_ROADMAP.md`, правило переноса).

## 6. Чем эта архитектура отвечает на Ф-1…Ф-10

| недостаток | механизм (детали — REGRESSION_PROTECTION) |
|---|---|
| Ф-1 копии правила | одна функция в библиотеке смысла (`dmath`: угол, длина, этаж, `botRand`, «время до точки») + запрет копии проверкой сборки |
| Ф-2 типы смысла | брендированные типы TS: `Px`, `GameUnits`, `PathLen`, `StraightDist`, `Seconds`, `Ticks`, `P2`/`P3`, `BotId`, `ZoneId` |
| Ф-3 обратная связь | `submit(claim): Result`; «A ждёт B» — общий тип ожидания с обязательной веткой «отказ» |
| Ф-4 неявный контекст | параметры — аргументами; запрет свойств функции как параметров и глобальных «контекстных» переменных |
| Ф-5 тег как уровень | `TaskKind` — объект в одной таблице; сборка падает на неописанной задаче |
| Ф-6 знание пишут все | `KnowledgeView` для решений; запись знания — только через `Knowledge` с источником |
| Ф-7 состояние вне игры | всё изменяемое — у владельцев с `save/restore`; проверка I-22, I-23 |
| Ф-8 порядок как правило | ничьи — явным правилом в арбитре; тест перестановки ботов (I-30) |
| Ф-9 статистика вместо тестов | регрессионные сцены с наборами A/B + инварианты на каждом изменении |
| Ф-10 гиганты | `tBrain`/`ctBrain` режутся по фазам на функции (перенос, бит в бит) |
