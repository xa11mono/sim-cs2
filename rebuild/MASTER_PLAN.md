# Генеральный план перестройки Р0–Р8

**Статус:** проект на утверждение владельцу (24.11.2026). После утверждения начинается только Р0; остальные этапы — по одному, после
приёмки предыдущего. Прогресс — `rebuild/JOURNAL.md`; среда — `rebuild/ENVIRONMENT.md`; отложенные игровые недостатки —
`rebuild/BEHAVIOR_BACKLOG.md`; архитектурные документы — `docs/architecture/README.md`.

Заменяет: фазы 0–4 `rebuild/PLAN.md` (15.11; фазы 0–2 и часть 3 выполнены — `rebuild/PROGRESS.md`), последовательности R0–R6
(`docs/reports/audit_2026-11-24/stage3/MIGRATION_ROADMAP.md`) и Р0–Р8 (`…/stage4/ROADMAP_CHANGES.md`). Эти документы остаются
источниками; при расхождении действует этот план.

## 1. Цель и границы

**Цель.** Устройство, в котором исправления накапливаются, а не ломают соседние механики: TypeScript strict для логики, Rust Native как
вычислительное ядро и WASM из того же исходника для браузера, компактная структура без числовых префиксов, общий движок и пакеты карт,
универсальные отметки, причинный дебаг, единые инструкции агентов, готовность к массовой симуляции и к подключению CS2 Manager.

**Кросс-браузерность обязательна** (владелец 24.11): игра работает в современных Chrome, Brave, Opera GX, Edge, Firefox и Safari.
Отдельного игрового кода под браузер нет: общие стандарты и резервные способы запуска, если возможности нет (Worker → главный поток,
WASM → TS-эталон, общая память → `postMessage`). Проверки встроены в этапы Р0, Р2, Р5, Р8 — отдельного глобального аудита нет.
Автоматически — Playwright (Chromium, Firefox, WebKit); где Playwright недостаточно (реальные Brave, Opera GX, Edge, Safari, звук,
ввод) — проверка в реальном браузере по списку.

**Сохраняется всё:** механики, поведение ботов, интерфейс, HUD, визуал, 3D, редакторы, песочница, повтор клатча, отметки, автономные HTML,
публикация страниц, замеры на ПК.

**Запрещено до приёмки (Р8):** новые игровые механики; улучшение поведения ботов; новые числовые параметры (каждое число берётся из
существующего кода, данных или источника; без этого — вопрос владельцу); изменение игровых формул и параметров. Единственное
намеренное изменение битов игры — этап Р2 (математика), по условиям владельца.

## 2. Правила для всех этапов

1. **Вид работ на версию один**: перенос / устройство · язык · скорость · технический ремонт снимка и изоляции · математика (Р2).
   Версия — ветка `vNNN` (буква — не закончено, `CLAUDE.md` §4); шаг — коммит; запись в `JOURNAL.md` — на каждый шаг.
2. **Доказательство эквивалентности** — три уровня, статистика матчей доказательством не является:
   - **Э1** — отпечаток бит в бит в закреплённой среде (`ENVIRONMENT.md`): `bash tools/measure/fingerprint.sh sim.html <папка>`,
     8 матчей, `diff -r` пусто; для каждой карты;
   - **Э2** — Э1 во всех средах запуска: движки Chromium, Firefox, WebKit, Node; страница и Worker; с Р7 — нативное ядро и WASM — с Р2;
   - **Э3** — объяснённое расхождение: локатор нашёл первый тик, поле и вызов; причина — заявленная в шаге и только она. Допустим только
     в Р2 и в технических ремонтах Т-1…Т-4, где изменение заявлено заранее.
3. **Необъяснённое расхождение = остановка шага.** Не «в шуме», не «известное»: локализация до операции, исправление переноса или откат.
4. **Старое не удаляется**, пока новое не принято. Переходник живёт до конца этапа.
5. **Откат**: `git revert` версий шага; база отпечатков и замеров предыдущего шага хранится (`tools/measure/runs/<метка>`).
6. **Общие условия остановки этапа**: проверка из «Приёмки» не проходит и причина не найдена; нужен ответ владельца; предпосылка этапа
   оказалась неверной (записать в журнал, пересмотреть план с владельцем); правка требует нового числового параметра.
7. **Прогоны** — на ПК через GitHub (`CLAUDE.md` §8); в облаке — отпечаток и короткие проверки.
8. **Отчёт владельцу** после каждого шага — простыми словами (`rebuild/RULES.md` п. 10).

Обозначения проверок: ✓ — инструмент есть; ◇ — создаётся в указанном шаге.

### Р6. Скорость на TypeScript — игра не меняется

**Обязательно (владелец 25.11):** рост памяти Ancient — куча JS 37,5 → 103 → 180 МБ к 20 000 / 40 000 тиков (Mirage 33 → 59 → 72 МБ;
`rebuild/evidence/R0/r0.11_speed_pc.json`): найти, что растёт, и проверить освобождение памяти после завершения матча (матч за матчем в одной
странице и в Node — куча возвращается к уровню после загрузки с точностью до разброса повторов).

Кандидаты К-1…К-10 (`stage3/PERFORMANCE_PLAN.md`): поиск пути на плотных массивах, повторы путей и лучей, `navAt`, первый тик раунда,
`knownSegCost`, память; кэш тяжёлой загрузки в пакете (таблица прострелов, граф) — равенство с расчётом при загрузке.

**Приёмка:** Э2 после каждой оптимизации; тест «без кэша» (кэш выключен — тот же результат); выигрыш больше разброса повторов того же
замера (база Р0.11). **Остановка:** нет выигрыша сверх разброса — шаг не принимается. **Откат:** по шагу.

### Р7. Rust-ядра — нативно и WASM из одного исходника — игра не меняется

Кандидаты по замерам Р0.11 / Р6: путь (`zoneDijkstra` + `knownSegCost`), лучи (`m3Cast` / `m3SegTri`), полёт гранаты
(`nadeLaunch` / `nadeStep`), прострелы при загрузке (`computeZoneDanger`), граф при загрузке (`rebuildNav`). Одна библиотека
`kernels/` → нативно (N-API: Node, локальный режим, массовая симуляция) и WASM (страница, автономный HTML). Ядро — чистая функция
(данные пакета + запрос + явные параметры), без скрытого состояния; математика — `dmath` в Rust (`libm`).

Для каждого ядра: TS-эталон → Rust → **корпус реальных запросов** из матчей всех карт, каждый ответ бит в бит (не суммы) → Э2 во всех
средах (Chromium + WASM, Node + N-API) → польза в целевом сценарии (массовая симуляция, старт) больше разброса повторов, с ценой передачи
данных → принять или оставить TS с записанной причиной. TS-эталон остаётся.

**Приёмка:** каждый кандидат принят или оставлен с замером-причиной. **Остановка:** хоть один ответ корпуса расходится — локализация;
сборка Rust не воспроизводится на ПК. **Откат:** переключатель «ядро TS» на время этапа (временный, удаляется при приёмке).
