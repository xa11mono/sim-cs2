# Изменения дорожной карты миграции (этап 4)

Этап 4, 24.11.2026. Заменяет последовательность R0–R6 из `../stage3/MIGRATION_ROADMAP.md` §3; стратегия A (постепенная перестройка без
переписывания) остаётся. Причины изменений — `ARCHITECTURE_ADDENDUM.md` §0, §13. Миграция не начата.

## 1. Что меняется в правилах этапов

1. **Эквивалентность при чистом переносе — только бит в бит.** Строка этапа 3 «шаг не бит в бит → делится или проверяется 8/16 матчами»
   удалена. Расхождение → локатор (§3, Р0) → первый тик → поле → вызов → операция → исправление переноса. Шаг не принимается, пока
   расхождение не объяснено.
2. **Отпечаток привязан к среде.** До шага Р2 сравниваются только записи одной среды (браузер, версия, V8 / Node); в каждой записи —
   среда. После Р2 — равенство между средами становится обязательной проверкой.
3. **Поведение — после приёмки перестройки.** Бывший R5 этапа 3 вынесен за конец перестройки. Найденные ошибки этапов 1 / 2B лежат в
   реестре со статусом `confirmed`; сцены фиксируют **нынешнее** поведение (в том числе ошибочное), чтобы перенос его не менял.
4. **Четыре вида работ не смешиваются в одной версии**: устройство (бит в бит), язык (бит в бит), скорость (бит в бит), намеренное
   изменение чисел (только Р2 — нормализация математики, с локализацией каждого расхождения).
5. **Старое не удаляется**, пока новое не принято; откат — `git revert` версий шага; каждая версия — один вид работ.
6. Оценку объёма новых работ не даю до Р0: её надо считать по факту первого перенесённого канала, а не придумывать.

### Р5. Симуляция отдельно от показа — R3 этапа 3, плюс

- Worker в странице, **Н1** (Node + `worker_threads`), по желанию **Н2** (локальный режим) — один поток кадров;
- пакеты карт без потерь (`map3d` без base64; навмеш — Float64 или текст); приёмка — хэш битов каждого поля `MAP`, затем отпечаток;
- сборки: автономный HTML одной карты, автономный HTML всех карт, вариант B (движок + пакеты); сравнение снимков экрана до / после;
- отметки v2: пакет `mark.json` + `mark.md` + `mark.png`, одна команда `tools/sim.js mark …`; старые снимки — через переходник.

### Р6. Скорость на TypeScript — R4 этапа 3 без изменений

Плюс кэш тяжёлой загрузки в пакете (таблица прострелов, граф) — равенство с расчётом при загрузке бит в бит.

### Р7. Rust-ядра — по одному

Порядок по замерам Р0 / Р6 (кандидаты: путь, лучи, полёт гранаты, прострелы при загрузке, граф при загрузке). Для каждого:
TS-эталон → Rust (одна библиотека, нативно + WASM) → корпус реальных запросов из матчей всех карт: **каждый** ответ бит в бит → отпечаток
матчей во всех средах бит в бит → замер пользы в целевом сценарии против разброса повторов → принять или оставить TS с записанной причиной.
Эталон на TS остаётся.
