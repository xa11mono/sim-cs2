# Загрузка и производительность: измерения (v598, 24.11.2026)

Измерения сделаны на этой машине, на опубликованных страницах `ancient-radar.html` и `mirage-radar.html`.
Скрипты: `docs/audit/architecture/instruments/load_probe.py` (загрузка, кадры, память, профиль) и `mem_probe.py`
(память по фазам). Сырые прогоны: `results/load_raw_<карта>.json`, `results/memory_<карта>.json`, сводка —
`results/load_summary.json`.

## 1. Условия

| | |
|---|---|
| Машина | AMD Ryzen 7 7800X3D (8 ядер), 16,75 ГБ ОЗУ, Windows 10 19045 |
| GPU | NVIDIA GeForce RTX 3070 (D3D11), монитор 1920×1080 **200 Гц** |
| Браузер | Chromium 156.0.8078.4 (Playwright), **headed** (настоящий GPU), viewport 1400×900, DPR 1 |
| Загрузка | локальный HTTP-сервер (`python http.server`), `Cache-Control: max-age=3600`; без сети |
| Страница | опубликованная, как у владельца (минифицирована, со звуками и разминкой) |
| Замер | 3 прогона на карту; «холодный» — новый контекст браузера (пустой кэш), «повторный» — та же страница ещё раз |
| Кадры | после разминки нажимается «Начать матч», 5 с ожидания, затем 8 с замера подряд |
| 3D | кнопка «3D», 3 с на инициализацию, затем 8 с замера |

Измерительная копия: в страницу вставляются только `performance.mark` в известные точки (начало скрипта, литерал
`MAP`, `SND_DATA`, отметки, `rebuildNav` на загрузке, `freshMatch`, `warmStart`, конец скрипта) и обёртка
`requestAnimationFrame` для счёта кадров. Логика и данные не меняются. Контрольный прогон без вставок: готовность
1,04 с (Ancient) / 0,84 с (Mirage), ошибок нет — в пределах разброса прогонов.

**Что означают границы фаз:**
- `s0` — первый оператор скрипта: сюда входит ответ сервера, разбор HTML и **компиляция** скрипта (отдельно не
  разделяются — см. §7);
- `map1−map0` — создание литерала `MAP` (разбор и размещение данных);
- `nav1−nav0` — вызов `rebuildNav()` на загрузке (050): связи навмеша, порталы, этажи, уровни;
- `mk0` — время после `nav1`: `computeZoneDanger()` (060, карта прострелов через `m3()`/`m3Cast`), построение сайтов,
  про-слоёв и прочей инициализации верхнего уровня;
- `w1−w0` — `warmStart(1)`: `freshMatch` + снимок разминки + расстановка ботов;
- `s1` — конец скрипта; первый кадр игры — первый `requestAnimationFrame` после `s1`;
- готовность (`ready`) — момент, когда разминка уже идёт (метка `w1`), по стенным часам.

## 2. Время до готовности и до первого кадра

| | Ancient холодный | Ancient повторный | Mirage холодный | Mirage повторный |
|---|---:|---:|---:|---:|
| до готовности, с (3 прогона) | 1,23 / 1,01 / 1,01 | 0,81 / 0,82 / 0,83 | 1,09 / 0,81 / 0,85 | 0,59 / 0,57 / 0,57 |
| **медиана, с** | **1,01** | **0,82** | **0,85** | **0,57** |
| первый кадр интерфейса (`first-contentful-paint`), мс | 72 | 52 | 80 | 52 |
| первый кадр игры (rAF после `s1`), мс | 1005 | 812 | 836 | 564 |
| ответ сервера (`responseEnd`), мс | 117 | 87 | 88 | 58 |

Первый прогон каждой карты дольше (1,23 / 1,09 с) — это первый запуск браузера и первый разбор файла с диска;
устойчивое значение — 1,01 / 0,85 с холодного и 0,82 / 0,57 с повторного.

Повторная загрузка быстрее не из-за сети: браузер сообщает полный `transferSize` (15,8 / 9,4 МБ) и в повторном
прогоне — это кэш кода V8 и кэш файловой системы, а не HTTP-кэш. Разница 0,19–0,28 с — цена повторной компиляции
и первого чтения.

## 3. Разложение по фазам (медианы, мс)

| фаза | Ancient холодный | Ancient повторный | Mirage холодный | Mirage повторный |
|---|---:|---:|---:|---:|
| ответ сервера + разбор HTML до скрипта (`s0`) | 241 | 149 | 212 | 100 |
| — из него разбор HTML (`s0 − responseEnd`) | 119 | 53 | 116 | 42 |
| литерал `MAP` (данные карты) | 4,3 | 2,4 | 7,5 | 4,7 |
| `rebuildNav()` на загрузке | 444 | 417 | 218 | 187 |
| `computeZoneDanger` + остальная инициализация до отметок | 226 | 195 | 248 | 213 |
| звуки `SND_DATA` (литерал) | < 0,2 | < 0,2 | < 0,2 | < 0,2 |
| модуль отметок (`__SNAP` + `marks.js`) | 0,4 | 0,2 | 0,4 | 0,2 |
| `warmStart(1)` (разминка) | 30 | 26 | 45 | 37 |
| **весь скрипт (компиляция + выполнение)** | **720** | **645** | **539** | **449** |

Что это значит:

1. **Данные карты разбираются дёшево**: литерал `MAP` (11,4 / 5,0 МБ) — 2–8 мс. Основная цена не в разборе JSON,
   а в **производных структурах**: навмеш (187–444 мс) и таблица прострелов/видимость (195–248 мс).
2. `rebuildNav` у Ancient в 2,3 раза дороже, чем у Mirage (444 против 218 мс холодного), хотя навмеш у Ancient
   меньше (248 КБ против 400 КБ): Ancient строит связи по 3D-геометрии и этажам, и это дороже, чем объём JSON.
3. Звуки и отметки к загрузке почти не добавляют времени (литералы создаются мгновенно); их цена — байты и память,
   а не миллисекунды старта.
4. Разминка (`warmStart`) — 26–45 мс: `freshMatch` укладывается в единицы миллисекунд (2–3 мс), остальное — снимок
   состояния для отметок и расстановка ботов.

## 4. Где горит CPU на старте (профиль, холодный прогон)

Профилировщик CDP, интервал 200 мкс, от старта навигации до готовности + 0,8 с. Сумма выборки 1,81 с (Ancient) /
1,60 с (Mirage); в таблице — собственная доля функции.

| функция | Ancient, мс | Mirage, мс | что делает |
|---|---:|---:|---|
| `(idle)` | 512,0 | 714,0 | ожидание (сеть, кадры) |
| `(program)` | 488,6 | 253,5 | верхний уровень скрипта вне функций |
| `m3Cast` | 145,0 | 155,6 | лучи по 3D-геометрии (таблица прострелов) |
| `(anonymous)` | 126,9 | 148,3 | анонимные функции (обходы, колбэки) |
| `dec` | 105,1 | 28,4 | base64 → байты (`atob`-обвязка) |
| `zInflate` | 72,5 | 34,1 | распаковка zlib |
| `bits` | 58,0 | 15,3 | битовое чтение внутри inflate |
| `m3Load` | 56,2 | 8,2 | сборка структур геометрии |
| `m3SegTri` | 35,7 | 14,5 | пересечение отрезка с треугольником |
| `arr` | 24,6 | — | base64 → типизированный массив |
| `(garbage collector)` | 18,7 | 22,5 | сборка мусора |
| `mkSnapshot` | 12,0 | 19,6 | снимок состояния для разминки/отметок |
| `put`, `cellOf`, `segOverlap` | 11,7 / 9,2 / 8,8 | — / — / 20,2 | корзины геометрии |
| `computeZoneDanger` | 5,7 | 6,1 | карта прострелов (общая стоимость — в `m3Cast`) |
| `atob` | 5,4 | — | декодирование base64 |

Итого по смыслу: **распаковка и декодирование геометрии ≈ 270 мс (Ancient) / 92 мс (Mirage)**, **лучи видимости
(в основном `m3Cast`) ≈ 145–156 мс**, остальное — верхний уровень скрипта, GC и показ.

Замечание: `rebuildNav` в профиле почти не виден (2,7 мс собственных), хотя по меткам занимает 444 мс. Прямой замер
обёрткой вокруг вызова (`instruments/nav_timing.py`): 408,8 мс внутри вызова — метки верны; профилировщик относит
это время к `(program)`. Поэтому для фаз опираемся на метки, а профиль используем для функций, которые он видит.

## 5. Память

`performance.measureUserAgentSpecificMemory()` (страница отдаётся с COOP/COEP, поэтому доступен точный учёт),
JS-heap по CDP и приватная память всех процессов Chrome (`PrivateMemorySize64`).

| фаза | Ancient: страница | Ancient: Chrome private | Mirage: страница | Mirage: Chrome private |
|---|---:|---:|---:|---:|
| браузер до страницы | — | 105 МБ | — | 105 МБ |
| готово (разминка идёт) | **136,7 МБ** | 712,5 МБ | **79,8 МБ** | 640,9 МБ |
| матч идёт 10 с | 140,7 МБ | 685,8 МБ | 84,8 МБ | 641,0 МБ |
| 3D включён 5 с | 238,3 МБ | 1 111,6 МБ | 144,2 МБ | 858,1 МБ |

- «Страница» — то, что реально занимает игра (JS-куча + DOM + внешние буферы): 137 МБ Ancient против 80 МБ Mirage.
  Разница ≈ 57 МБ — это распакованная геометрия и её производные (Ancient 39,5 МБ распакованных блоков против 29,3 МБ
  у Mirage, плюс треугольники/корзины: у Ancient 956 тыс. треугольников в 3D-сцене против 88 тыс.).
- «Chrome private» включает браузер, GPU-процесс, кэш кода V8 и разделяемые страницы; для оценки «сколько добавит
  игра» годится разница с базой: **+607 МБ (Ancient) / +536 МБ (Mirage)**, из которых на страницу приходится
  137/80 МБ, остальное — процессы, код и буферы композитора. Цифра приватной памяти завышена относительно
  «диспетчера задач» Chrome, поэтому в отчёте она дана как измеренная величина, а не как «память игры».
- 3D добавляет 100 МБ (Ancient) / 64 МБ (Mirage) к памяти страницы: сцена строится из тех же треугольников.

## 6. Кадры и главный поток

| | Ancient | Mirage |
|---|---:|---:|
| 2D, живой матч: FPS (медиана 3 прогонов) | 199,4 | 199,2 |
| интервал кадра p50 / p95, мс | 5,0 / 5,1 | 5,0 / 5,1 |
| длинные задачи (>50 мс) за 8 с | 0 | 0 |
| 3D: FPS | 200,0 | 200,0 |
| 3D: интервал p50 / p95, мс | 5,0 / 5,1 | 5,0 / 5,1 |
| 3D: треугольников в сцене | 956 147 | 87 791 |
| DOM-узлов | 2 251 | 2 250 |

Монитор 200 Гц, и обе карты упираются в частоту обновления: и 2D, и 3D рисуются за ~5 мс на кадр, длинных задач
в матче нет. Это **не значит, что запас бесконечен**: Ancient в 3D при 956 тыс. треугольников на этой GPU ещё
укладывается в 5 мс, но на слабой видеокарте или в программном рендеринге (headless Chromium = SwiftShader)
картина другая — см. §7.

Симуляция идёт фиксированными тиками 64 Гц и не измеряется в FPS; FPS отражает только показ. Отдельного замера
«сколько тиков в секунду» в этом аудите нет, потому что тик задаётся часами, а не кадром; стоимость тика видна
в профиле матча (не снимался — профиль только старта).

## 7. Ограничения измерений

- **Компиляция JS не отделена от разбора HTML**: `s0` включает и то, и другое. Утверждение «parse+compile ≈ s0 −
  responseEnd» — верхняя граница; точное разделение требует `v8.compile`/трейсинга, в этом аудите не делалось.
- **Повторный запуск — не «нулевой кэш»**: браузер сообщает полный размер передачи; повторный прогон ускоряется
  кэшем кода V8 и ФС. Отдельно «HTTP-кэш» не проверялся (локальный сервер отдаёт файл целиком).
- **`(program)` 250–490 мс** — это время верхнего уровня, включая циклы инициализации, которые профилировщик не
  относит к именованным функциям; детальнее — только целевой профиль по фазам (следующий шаг, не в этом аудите).
- **3D в headless не показателен**: headless Chromium на этой машине использует SwiftShader (программный WebGL2),
  поэтому все цифры 3D выше — headed с настоящей RTX 3070. Для сравнения: прошлый замер (`bench/stage3/results/
  frame_*.json`, headless, 20 с) дал 22,6 % занятости главного потока, 3 длинные задачи (медиана 182 мс) и рост
  heap 32,5 → 54,7 МБ — это другой браузерный режим, цифры несравнимы напрямую.
- **Первый прогон** включает прогрев браузера/GPU; медиана и минимум даны отдельно, «холодный» — это не «холодная
  машина после перезагрузки».
- FPS 199–200 — это **потолок монитора**, а не предел игры: при 200 Гц кадр длится 5 мс, и обе карты его укладывают.

## 8. Что из этого следует

1. **Размер файла ≠ время запуска.** 15,8 МБ Ancient открываются за 1,0 с, 9,4 МБ Mirage — за 0,85 с: разница
   в размере 6,4 МБ даёт 0,16 с, потому что данные читаются быстро, а дорого стоит **инициализация** (навмеш +
   видимость = 0,67 с / 0,47 с).
2. **Главный резерв старта — навмеш и таблица прострелов**, а не размер `MAP`. Их ускорение (кэш между запусками,
   ленивая часть работы, Rust/WASM) даёт больше, чем снятие base64.
3. **Снятие base64 даёт ~270 мс CPU (Ancient) и 2,5 МБ** — заметно, но это второй по важности резерв.
4. **Память** определяется распакованной геометрией: 137 МБ страницы Ancient против 80 МБ Mirage. Для 7 карт в одном
   процессе это станет ограничением — данные карт надо уметь выгружать/переключать, а не держать все сразу.
5. **Кадры не проблема на этой машине** (200 Гц, 0 длинных задач), но 3D Ancient — самая тяжёлая сцена; при
   переносе на слабое железо/WASM это первое, что просядет.
