## 21.10.2026 — В4 (v394, М138): лайнап = записанный бросок про; смоки-лайнапы — заплатка «доводка в точку про»
- Лайнап набора (`lineups.json` → `throws`) — записанные броски про (≥ 3 одинаковых в ≥ 2 демках: место ±6 ед. / с хода ±16,
  поворот / наклон ±0,3°, движение, присед, разбег ±40 ед/с — **проектные** только «с хода» и разбег), до 8 на вариант; сила и прыжок
  на бинде — физикой по разрыву у про (`tools/nades/lineups_rec.py`, `lineups_fit.js`). Записи набора («когда», доля раундов) —
  прежние: меняется только «как кидают». Бот берёт вариант ближе к себе и один из записанных бросков (разброс — как у про), встаёт
  точно, делает записанный разбег (0,4 с — **проектное число**) и кидает этот бросок через тот же `throwNade` (`nadeRecRelease`).
- **ЗАПЛАТКА** (решение владельца 21.10, вариант «а»): смок-лайнап летит по физике, последние 0,3 с (**проектное число**) доводится
  в точку разрыва про и рвётся во время про (`smokePinStep`, 400). Причина: В2б — физика повторяет лайнапы смоков в 24–25 %, полёт
  по ступеням и краям неустойчив. **Снять**, когда физика смоков даст ≥ 60–70 % (`node tools/nades/lineups_fit.js <карта>`).
  Свои смоки (не лайнапы) не трогает.
- Удалено: `BAL.lobErr` и `execErr` для гранат (выдуманный промах), заплатка «с разбега, бот стоит» (`NADE_RUN_V`, поиск «с разбега»
  в `nadeAim`), `nadeSolve` для лайнапов с записью. Записи без строгого лайнапа (у про — «на глаз»: флешки / HE в основном) пока
  кидаются физикой как своя граната — В5.
- Проверка без матчей (записанный бросок → туда же, где у про): флешки 81–89 %, HE 65–70 %, молотовы 46–51 %, смоки по физике
  27–45 % (в игре — 100 % заплаткой). Прогоны ПК 34–36, 16 матчей на карту против v393: гранат −3 / +1 % (Ancient CT / T),
  −2 / −5 % (Mirage) — в пределах 10 %; `nav` Mirage −21 %, `tug` −74 / −46 % (ушло мелькание «пост → лайнап → пост»); остальное
  в шуме. Влито в main. Попутно: подпись версии страницы (`mkpub.py`) — наибольшая версия из последней записи DECISIONS.
