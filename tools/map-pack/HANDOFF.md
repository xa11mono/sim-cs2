# Р5.5 · Пакеты Ancient и Mirage

Основа — `v636a` (`7aba8b8`). Прототип находится в `tools/map-pack/`. Выбор полей и актуальность запечённых бросков определяет действующий `src/mapset.py`. Проверка сверяет набор полей с `tools/map/map_manifest.json` с учётом объединения `map.json` с корнем и необязательного `demorounds.json`.

## Формат и точность

`.simmap` начинается с `SIMMAP01`, затем длина JSON-заголовка (uint32 LE), заголовок в UTF-8 и блоки map3d. Геометрия сохраняет существующие zlib-потоки байт в байт. В пакете они лежат как двоичные данные без base64. Навмеш и остальные числа остаются JSON. Запись сохраняет в том числе знак нуля. PNG радара сохраняет действующий интерфейс `MAP.radar`. `load.mjs` читает пакет из `Uint8Array` в Node или браузере и выдаёт карту для отдельного матча.

| Карта | JSON до упаковки, байт | Пакет, байт | Проверено чисел JSON | Проверено двоичных блоков |
|---|---:|---:|---:|---:|
| Ancient | 11 426 818 | 8 973 121 | 232 117 | 23 |
| Mirage | 5 040 305 | 4 518 167 | 371 750 | 23 |

На каждой карте проверены структура и порядок полей, каждый JS Number через `Object.is`, сжатые и распакованные байты всех блоков, массивы и пространственные корзины действующего `m3Load`. В `evidence.json` записаны SHA-256 пакетов и Float64 LE по полям, число лучей и столкновений гранат. Встроенная проверка отвергает чужую сигнатуру, усечённый пакет и лишние байты. SHA-256 можно проверять при доставке пакета из внешнего источника. Контейнер v1 предназначен для данных репозитория.

## Что можно разделить между матчами

| Данные | Размещение |
|---|---|
| Двоичные блоки пакета, треугольники, диапазоны высот, геометрия выпуклых блоков, колонки и данные этажей | Один экземпляр для чтения. Два экземпляра матча используют общие массивы в одном процессе. Два тестовых `worker_threads` прочитали общие сжатые блоки и готовые треугольники через `SharedArrayBuffer`. |
| `bTri` / `bHull` | Можно читать вместе внутри одного JS isolate. Для разделения между потоками нужна плоская структура с сохранением порядка элементов корзин. |
| `bSeen` / `bStamp`, `nTriSeen` / `nHullSeen` / `nStamp`, `nTriPl` / `nHullPl` | Свои у каждого матча. Запросы меняют штампы и создают записи в кэшах. `nTriXY` сейчас создаётся лениво на матче, его можно вынести после отдельного теста точности. |
| `fill` / `F.pl`, `M3_SOLID` | Свои для эффективной карты, учитывают укрытия и навмеш. `F.pl` заполняется во время столкновений. |
| `NAVAREAS`, `ZONEMAP`, граф, опасности, стены, редакторские наложения | Исходник пакета общий. Рабочие экземпляры отдельные, потому что загрузка и редакторы меняют координаты, порядок вершин, связи и производные кэши. См. `zones.js`, `paths.js`, `zone-danger.js`. |
| Состояние матча | Отдельные боты, знание команд, часы, счёт, физика объектов, диагностические буферы, повторы и все зависящие от них кэши (`rebuild/state_classes.json`). |

Треугольники и диапазоны высот занимают 42 070 468 байт на Ancient и 3 862 804 байта на Mirage. Это размер массивов, а не замер RSS на матч. Прототип делит между потоками отдельный массив треугольников. TypedArray и SharedArrayBuffer доступны для записи на уровне JavaScript, поэтому общие представления выдаются только доверенному коду чтения. `loadSharedGeometry` заранее материализует ленивые колонки, а источник и оболочка матча владеют своими изменяемыми полями.

## Воспроизведение

```sh
mkdir -p dist
node tools/map-pack/check.mjs dist/map-pack-evidence.json
for map in ancient mirage; do
  node tools/map-pack/pack.mjs "$map" "dist/$map.simmap"
  python3 tools/node/core_build.py --map "$map" "dist/core-$map.js"
  node tools/map-pack/fingerprint.mjs "dist/core-$map.js" "dist/$map.simmap" "dist/$map-fp-short.json" --ticks=3000 3 7
done
```

`fingerprint.mjs` использует существующий `tools/measure/fingerprint.js` на двух версиях собранного ядра. Вариант пакета читает блоки напрямую через временный адаптер `geometry-adapter.mjs`. Файлы движка и штатные сборщики общие для обеих версий. Без `--ticks` запускается полный набор матчей Э1. Короткая проверка совпала на двух номерах матча каждой карты, по 3000 тиков (Node 24.22.3, Linux). В матче 3 сверены и первые 12 000 тиков каждой карты, включая один завершённый раунд Ancient и два Mirage. Результаты лежат в `*-short.json` и `*-events.json`. После подключения к штатному `boot(map)` нужно подтвердить полный Э1 и отдельно проверять параллельные матчи Р5.8.
