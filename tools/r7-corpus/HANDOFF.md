# Р7 · Корпуса запросов к вычислительным функциям

Основа — `v636a` (`7aba8b8`). Инструменты работают со штатной локальной сборкой `tools/node/core_build.py`. Сборка для захвата оборачивает три функции в памяти процесса и записывает вызовы после начала матча. Упаковка, трассировка и Rust находятся в `tools/r7-corpus/`.

## Что покрыто

| Корпус | Реальный вызов | Сравниваемый результат | Запросов Ancient / Mirage |
|---|---|---|---:|
| Навигация | `knownSegCost` из `zoneDijkstra` | Штраф участка пути с фактическими точками и константами поиска | 24 / 24 |
| Видимость | `m3SegTri` из геометрии движка | Доля отрезка в точке пересечения или `-1` | 24 / 24 |
| Физика гранат | `m3BoxPlanes` из `m3NadeTrace` | Доля хода и три компоненты нормали либо `null` | 24 / 24 |

Матч 3, первые 5000 тиков каждой карты. Для операции берутся первые 12 уникальных запросов с попаданием/ненулевой стоимостью и первые 12 с промахом/нулевой стоимостью. В архиве каждой карты лежит один JSON. У каждого запроса есть тик, операция, полный вход и результат. Числа записаны HEX-последовательностями восьми байтов IEEE 754 LE. Пустой результат означает `null`. SHA-256 сборки в корпусе фиксирует происхождение, поэтому корпус пригоден и для сравнения будущей сборки с этим эталоном.

В основе портов навигации и треугольника — исследования `docs/reports/audit_2026-11-24/stage3/bench/rdj`. В сравнении применяются операции и допуски из актуального движка (например, порог определителя треугольника из `geometry3d.js`). Тест не суммирует выходы. Он заново вычисляет ответ действующей функции через типизированный адаптер `reference.ts`, затем сравнивает каждый байт с ответами нативного исполняемого файла и WASM из одного Rust crate. Ядра используют арифметику IEEE 754 и `sqrt`. Для этих трёх операций зависимость от `libm` отсутствует.

## Воспроизведение

Node 24+, Python 3, Cargo, цель Rust `wasm32-unknown-unknown`. Команды запускаются из корня репозитория.

```sh
python3 tools/node/core_build.py --map ancient dist/core-ancient.js
python3 tools/node/core_build.py --map mirage dist/core-mirage.js
cargo build --locked --release --manifest-path tools/r7-corpus/kernel/Cargo.toml
cargo build --locked --release --manifest-path tools/r7-corpus/kernel/Cargo.toml --target wasm32-unknown-unknown --lib
node tools/r7-corpus/capture.mjs dist/core-ancient.js ancient dist/r7-ancient.json 5000 12
node tools/r7-corpus/capture.mjs dist/core-mirage.js mirage dist/r7-mirage.json 5000 12
for map in ancient mirage; do
  node tools/r7-corpus/check.mjs "dist/core-$map.js" "tools/r7-corpus/fixtures/$map.json.gz" \
    tools/r7-corpus/kernel/target/release/sim-r7-parity \
    tools/r7-corpus/kernel/target/wasm32-unknown-unknown/release/sim_r7_parity.wasm
done
```

Для Windows нативный файл имеет расширение `.exe`. Сборка и прогоны доказательства выполнены на Linux x86-64, Node 24.22.3, Rust 1.100.0. **144 из 144 ответов совпали** во всех трёх реализациях. Повторный захват дал те же JSON побайтно. При подмене одного бита эталона тест остановился с указанием карты, матча, тика и номера запроса. Детализация — в `evidence.jsonl`.

## Граница подготовки

Точки входа этого прототипа — три функции в таблице. Э2 для полных `zoneDijkstra`, `m3Cast`, `nadeLaunch` и `nadeStep` остаётся частью Р7. Полный поиск требует зафиксировать идентичность графа, порядок рёбер, промежуточную точку входа в участок, кэш продолжения, тактические данные и обработку ближайшей достижимой цели. Полный луч требует выбора столбиков, корзин, блоков и порядка равных попаданий. Для полёта нужно записывать начальное состояние и вызовы трассировки в порядке их фактического потребления. Нативный прототип сейчас запускается как отдельный процесс. Браузерный WASM и N-API остаются отдельными проверками интеграции Р7.
