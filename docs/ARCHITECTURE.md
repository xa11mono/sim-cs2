## Как устроен исходник
С v177 игра — маленькие файлы (карта выше). `src/build.py` склеивает их,
вставляет данные из `src/data/` на места меток `@@DATA:…@@` / `@@PNG:…@@` и
генерируемое (список переменных для перемотки, пункты PRINCIPLES, модуль
`src/marks.js`). Склейка дала ту же страницу, что один файл `game.html` (бит
в бит). Инструмент отметок (`src/marks.js`) мозг ботов не трогает; снимок всей
игры — `mkSnapshot`/`mkRestore`, в файл — `mkPack`/`mkUnpack`, открыть
отметку — `mkOpenSnap` (на странице) и `tools/mark_open.js` (без экрана).
История: до v168 — orig.html + 24 патча, v168–v176 — один `src/game.html`.

## Почему так вышло
Каждая жалоба решалась новым правилом на переключателе; старое не удалялось.
Попытка «переделать всё» на ~v145–148 (новый взгляд, оценка угроз, задача
«держать район») тоже добавила новые системы рядом со старыми.

## Из чего состоит (кратко)
- **Карта:** радар Ancient, стены нарисованы вручную (`MANUAL_WALLS`, ~540
  отрезков), навмеш для путей, ~60 именованных зон (`ZONEMAP`, `BZ`).
- **Знание о врагах (с v169 — одна картина на команду):**
  - вход — только общий канал: увидел — сразу (как радар), услышал/сказал —
    с задержкой голоса (`commSend` → `intelPush`). Журнал канала
    `teamIntel[team].sig` — лента событий (смерти, фраги, гранаты, звуки);
  - картина — карта вероятностей по зонам `belief` + последнее наблюдение по
    каждому врагу `beliefLast` (с пометкой «проверили — пусто») + `LAST_CLEAR`
    / `REACH`. Читают её через `picKnown` (кому из наблюдений ещё верить),
    `picRecent` (свежие наблюдения), `picNear` / `intelEstimate` (сколько рядом),
    `picOutnumbered` (у точки их на 2+ больше, чем нас);
  - у бота лично — только его органы чувств: что сам видел (`lastIntel`) и
    слышал (`heardSound`). Тиммейты туда больше не пишут;
  - колл CT (`ct.call`) — одно место, считает по картине;
  - события (смерти, фраги, звуки по порядку) читаются только через
    `picEvents` — «ленту событий» картины;
  - память о сопернике между раундами — одна, `MEMORY` (тактики и итоги
    раундов, любимые углы, расстановки CT, агрессия, AWP/раши, где умирали T,
    куда кидали гранаты); её половинная копия между матчами — `OPP` в браузере.
- **Позиция:** роль и расстановка (`ctSetup`, тактики T) → `setPost`; поверх —
  перестановки после фрага, откаты, размены, лайнапы, про-точки (`proSnap`),
  перераспределение сайта (`siteRebalanceTick`), «минус мидер», пост-плант,
  ретейк, клатч и т.д.
  **Кто кого перебивает (с v173) — одна таблица `TASK_PRIO`:** у бота одна
  текущая задача `b._task` (вид, важность, срок; `holdTask` / `dropTask` /
  `taskOn`). Пост с меньшей важностью её не перебивает. Порядок: бомба (плант,
  дефуз, отход от взрыва, «не дать заложить») 10 → размен 9 → сейв, подобрать
  бомбу 8 → ретейк, пост-плант 7 → лайнап 6 → подбор оружия, ждать у смока 5 →
  реакции в бою «repos» (после фрага, дабл-пик, добить, мало HP…) 4 → охота на
  последнего 3 → проба T 2 → пост роли/плана 1. Отдельно остались: маршрут
  (`_route` — это путь, а не решение), замок перераспределения сайта (`_rebal`)
  и две подмены точки (`holdShift`, `proSnap`) — до следующей попытки шага
  «позиция» (первая, «держать сайт», откатана — см. DECISIONS, v173).
- **Взгляд (с v171 — одна цепочка без отдельных ступеней; с v176 — вес угла
  только от реальной угрозы):** видимый враг → задачи со своим взглядом
  (прикрыть ослеплённого, спам, роум, фейк) → делёж углов команды `lookPlan`
  раз в 8 тиков → одна проверка «не в стену» `wallSafeLook` → плавность
  `smoothLookFilter` (+ «бросает гранату — смотрит туда»). Внутри дележа
  кандидаты (`lookCands`): угрозы зон и входы в свою зону, свежий контакт (по
  имени врага), на сборе ретейка — выходы с сайта, где бомба. Вес угрозы — из
  картины команды: вероятность врага (belief), «враг мог дойти» `reachW` по
  `REACH` (не мог — 0; путь открыт давно и никто не вышел — гаснет до 15%) и
  «давно не проверяли» (только если дойти мог). «Как у про» (`proDirs`) и
  угол поста — не кандидаты, а подсказки ×1,2 угрозе в их сторону; угол поста
  берётся сам, только если угроз нет совсем. Взгляд украдкой на бегу берёт
  кандидатов из того же дележа.
- **Гранаты (с v172 — одна дверь):** каждая граната — только заказ `assignNade`
  → выполнение `updateNadeTasks` (единственное место, где вызывается бросок
  `throwNade`). В двери общие проверки: не дубль того же типа в ту же точку, не
  смок в стоящий смок, и (Г1) флешка не летит, если по картине команды враг
  виден прямо сейчас в 400 px от точки хлопка (`flashIntoFight`).
  Кто заказывает:
  - запланированные: про-лайнапы из демок (221, `PRO_LINEUPS_RAW`) и свои
    (`lineupTick`, тоже через дверь); встроенные сценарии `nadeBrains` (инста,
    фейк, выход, колл CT, на дефуз, «в смок — не дать занять сайт») летят, только
    если в каталоге нет лайнапа на ту же ситуацию (`builtinAllowed`: про-лайнап
    покрывает или свой лайнап её заменяет) — без запасного «если не нашёл
    бросающего»;
  - реакции (по одному механизму на ситуацию): граната по свежему врагу
    `nadeOnEnemy` (мало HP — всё во врага, HE добить, HE в стак, выкурить),
    комбо `nadeCombos`, молотов на раш и ранняя граната CT (`nadeReact`), HE в
    смок `smokeHeTick`, смок на AWP `awpSmokeTick`, флешка себе под пик
    `prePeekDecide`, на отходе (`nadeBrains`);
  - внутри чужих решений (через ту же дверь): проба T (`tProbes`), поп на убийцу
    (`intelDeath`), ретейк — флешка и смок только `retakeUtil` (+ смок под
    дефуз в `updateRetake`), ранний пик CT (`ctEarlyPeek`).
  Детекторы — `docs/DETECTORS.md`, `tools/measure/nades.py`.
- **Экономика:** правила CS2 (лосс-бонус 1400…3400, победа 3250/3500, +800 за
  плант), решение закупа `decideRoundType`, фулл учитывает гранаты.
- **Данные про:** 10 матчей / 268 раундов на Ancient (`data/demos`, `data/pro`):
  позиции и взгляд каждые 0,25 с, фраги, гранаты, планты.

- **Подача (с v178):** киллфид как в CS2 — `Убийца + Ассистент · силуэт
  оружия · значки · Жертва` (`feedKill`/`renderFeed`, 20_hud.js). Силуэты (с v179) нарисованы вручную по форме настоящего оружия — таблица `WEAPON_ICON` (сетка высотой 24), значки — `KF_MOD`; иконки из файлов игры не используются. Ассист —
  другой игрок снял жертве 40+ HP (`noteDmg` — одно место учёта урона, оно же
  для MVP) или ослепил её (`_blindBy`). Значки приходят из стрельбы: через смок,
  ноускоп, убийца ослеплён, хедшот; прострела стен в игре нет. Консоль —
  одна запись `logEvent(текст, вид)`: вид kill/bomb/team/voice/round — в
  консоль, без вида — отладка, только в скрытом журнале (галочка «отладка»).

## Направление (обсуждено 01.10)
Цель — бот «понимает»: одна картина мира (что известно, откуда может выйти
враг) + несколько целей (не умереть зря, держать угол, быть рядом для
размена, играть на бомбу) → действие выбирается из них, а не из сотни
правил «если X — делай Y». Демки — для сверки и для норм, а не для копирования.
Перед этим — ревизия и план на согласование.
