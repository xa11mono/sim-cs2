## 11.10.2026 — Ротация: одно решение до новой инфы; выбитую бомбу держат (v262, пункты К4–К5)

**Что (всё в `ctBrain`).** К4. Отметка m1791719440440: 8 и 9 бегут B → A → B, 8 застревает. Повтор матча владельца не
воспроизвёлся (без «Экспорта проекта» матч расходится уже к раунду 5), причина найдена в нашем матче 1 и в журнале снимка:
колл скакал A ↔ B по разнице «счёта» в доли (A1 ↔ B1,1 за 16 тиков), ротация собиралась заново каждый тик (подтаял счёт,
«разошлись по одному», терпение — ротатора снимали), «давно тихо — по местам» снимал колл на полпути (в отметке: 448,5 с).
Теперь `ct.go` — кого послали на сайт колла; посланный идёт до конца, новых шлют сколько не хватает. Колл на другой сайт при
идущей ротации — только по новой инфе о T: там свежо видели/слышали/убили нашего и T там больше (округлённо), или бомба /
плант (**проектное правило**; «сайт пустой» — не инфа о T). Тишина колл с идущей ротацией не снимает. Удалено: «уже стоящий
на ротации не сбрасывается» (заменено `ct.go`). К5. Выбитая бомба (C4 у тела T; передача — не в счёт), которую видел кто-то
из CT, — знание команды: держит ближайший (точка с укрытия, откуда видно бомбу), **и при колле** (раньше только без колла,
а колл при убитом носителе есть в 97 % случаев — держащий не работал); для колла бомба — как замеченный носитель, колл и
ротация идут на её сторону. Держащий погиб — держит следующий ближайший. Источник — PRO_PLAY 6б-2 [28].
**Цифры (12 матчей; про / v261 / v262).** Разворотов и повторных посылок на 100 ротаций — / 37,9 / 6,8; снятий с ротации

## 11.10.2026 — CT на сборе ретейка не стоит спиной к входу со стороны T (v260, пункт В3)

**Что.** Отметка m1791718028039: CT 3 в Back Halls смотрит в Alley, First Lane за спиной в 170 px, 3 T на B. Три причины, три
правки. 1) «Смотреть спину» на сборе получал ближайший к проходу между сайтами в начале ретейка — и держал это, даже став
передним. Теперь — замыкающий (дальше всех от бомбы), пересмотр — когда смотрящий оказался впереди всех (**проектное
правило**: в разборах ретейка Refrag/The Spike прямого ответа нет). 2) `setPost` не принимал новое направление взгляда на той
же точке (id поста — задача + точка): у CT 3 навсегда оставалось «смотри в Alley». Теперь направление обновляется, путь — нет.
3) Угроза входа считалась по числу зон (сосед, сосед соседа), а не по расстоянию: Site B — подзона внутри B Site, и First Lane
от неё в трёх зонах, хотя это ~250 px. Теперь `nbrThreat` — враги по длине пути до входа, вес exp(−путь/LOOK.nearPx = 360)
(**проектное число**), заменяет оба прежних «соседа». 4) Стоя без свежей инфы бот изредка проверяет второй сильный угол
сбоку/за спиной (≥ половины главного, ≥ 90°, раз в 4–8 с на 1,2 с — **проектные числа** `LOOK.check*`). Угол, который держит
тиммейт, ослаблен дележом и не проверяется. LOOK, SL и кэш BZ_WALK — больше не в снимке отметки (таблицы).
**Цифры (12 матчей; про / v259 / v260).** Спиной вперёд на бегу после планта CT 6,5 / 5,4 / 6,8 %, T 9,8 / 10,3 / 11,8 %;
**до планта хуже**: CT 6,8 / 8,8 / 10,2 %, T 5,2 / 6,9 / 9,1 % (угроза по расстоянию даёт больше целей сзади на ходу);
