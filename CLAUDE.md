# Правила работы над проектом (для Claude)

Проект: симулятор раундов CS2 на карте Ancient (радар, 10 ботов), цель — боты
играют и выглядят как про-игроки. Владелец — не программист, оценивает глазами
и по цифрам сравнения с демками про.

**Главный принцип игры (06.10).** Бот знает и делает то, что может знать и делать
настоящий игрок в про-матче — не больше и не меньше (восприятие + тимспик + общая
картина команды). Никаких правил под отдельную ситуацию и никакого «как у про»
внутри мозга: демки — только для сверки. Подробно — начало docs/PRINCIPLES.md.

**Сейчас (с v239, 10.10) игра — снова v166** (решение владельца: v166 по движению, гранатам и экономике ближе к про;
переделка v197–v238 — в ветке `rebuild-v238`). Игра — v166 (бит в бит), с v377 исходник — модули `src/game/NNN_*.js` (раньше один `src/game.html`). Что будем менять в
v166 — `docs/V166_CHANGES.md` (список владельца). Главный принцип и правила ниже — в силе.
С v240 в v166 — знание о врагах из переделки (`KNOW`, `know*`: гипотезы held/moved/moved_unknown); карту
`belief`, которую читают решения v166, собирает из них `beliefTick` (старое растекание весов — в ветке `v166-weights`).
С v241 — карта переделки (стены, высоты, укрытия, прострелы + редактор), видимость в 3D, войс и киллфид/табло переделки.

## Экономия лимита — обязательно (07.10)
Каждый шаг пересылает весь разговор заново, поэтому лишнее чтение дорого вдвойне.
- **В начале чата ничего не читать «для контекста».** Карта файлов — ниже, этого
  хватает. Доки (`ARCHITECTURE.md`, `DECISIONS.md`, `PRINCIPLES.md`, `docs/tasks/`)
  открывать только когда задача их касается, и только нужный раздел:
  `grep -n` по слову → `Read` с offset/limit. `docs/archive/` — не открывать.
- **Код читать кусками, а не файлами.** Сначала `grep -n 'имяФункции' src/game/*.js`,
  потом `Read` нужных строк (offset/limit). Файл целиком — только если он
  меньше ~150 строк или правка правда затрагивает весь файл.
- **Никогда не читать целиком** (только grep / кусок по строкам):
  `ancient-radar.html` и `sim.html` (сборки, ~1 МБ — собираются скриптами из `src/`,
  их содержимое и так известно), набор карты `data/maps/*/*.json` и `radar.png` (кроме `map.json` и
  нужного куска `tactics.json`), `src/data/navmesh.json`, `heights.json`,
  `zonemap.json`, `data/pro/*`, `data/demos/*`, `tools/measure/results/*`,
  `*.diff`, картинки.
- **Не запускать субагентов** (Agent/Explore) и не сканировать весь проект без
  прямой просьбы владельца.
- **Вывод команд — коротко:** `| tail`, `| head`, `grep`. Не печатать большие
  JSON/CSV и длинные логи в разговор.
- Базу страницы (отметки, правки редактора карты) забирать **только когда владелец
  просит** или задача от них зависит — не в каждом чате.
- Подтверждение понимания и план (см. ниже) — **одним сообщением**, а не двумя
  раундами.
- MCP codebase-memory в облачных сессиях не использовать: он индексирует папку на
  компьютере владельца, а не облачную копию репо.

## Правила владельца
- **Разбор правок по отметкам (29.10, владелец; главнее цифр).** Владелец смотрит матч (Mirage, Ancient), шлёт пункты + отметки + скриншоты
  (N-й скриншот = N-й пункт). На каждый пункт: найти **все** причины по снимку отметки (проверить каждую побочную странность — влияет
  ли на проблему; «не проверял» — нельзя); как должно быть — **только как расписал владелец**, ничего не придумывать (ни поведения, ни
  чисел); не расписал / не знаю — выписать ситуации вопросами, владелец спросит у знающей нейросети. Правка → прогнать **этот раунд**
  (снимок отметки) и посмотреть: бот играет, как написал владелец, — пункт закрыт; нет — правка дальше. Все пункты карты закрыты —
  8 матчей этой карты на ПК: производительность и нет ли тех же проблем в других раундах. Мерило — «проблема ушла», а не % цифр.
- **Как работаем, чтобы цифры двигались (17.10)** — `docs/tasks/work_rules.md`, обязательно: замер шума на 6–10 матчах, пять главных цифр
  одной таблицей, у каждой правки — цифра и направление (не сдвинулась — откат), чинить снизу вверх (движок и данные → мозг), реже
  переделывать устройство.
- **Оформление страницы — по репозиториям владельца** (`docs/DESIGN_SOURCES.md`: ссылки и что из них применяем). Любую
  правку вида (табло, панели, эффекты, меню) сверять с ними, а не делать «на глаз». *(12.10)*
- **Все прогоны — на ПК владельца через GitHub (21.10, владелец), в облаке матчи не гонять.** Задание — `tools/measure/request.json`
  в ветке `measure/<имя>` (пуш запускает `.github/workflows/measure.yml`), результаты — ветка `pc-results/<N>` (`<метка>/rec_<m>.json.gz`),
  ждать — `gh run list` / `gh run view`; как устроено — `docs/tasks/work_rules.md`, «На ПК владельца». Сторож берётся из ветки
  `measure/…`, игра — из `ref`: правка только сторожа игру не меняет — проверять совпадением с прошлым прогоном той же версии (бит в бит),
