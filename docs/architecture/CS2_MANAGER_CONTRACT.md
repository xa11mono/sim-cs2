# Контракт матча для CS2 Manager (Р5.9, 26.11.2026)

Только интерфейс, без интеграции (MASTER_PLAN Р5.9). Реализация — ядро без показа (Р5.3, `runMatch`), запуск — Node (`tools/node/core_run.js`)
или потоки (`tools/node/mass_run.js`, Р5.8). Игра в этом контракте та же, что в странице: Э2 (ядро = страница, бит в бит), Р5.2 (Worker).

## Как запустить
| способ | что | пример |
|---|---|---|
| ядро со встроенной картой | `dist/core-<карта>.js` (`python3 tools/node/core_build.py --map <карта>`) | `require('tools/node/core_run.js').load(core)` → `__ev` |
| ядро без карты + пакет карты | `dist/core-pack.js` (`core_build.py --pack`) + `<карта>.simmap` (`node tools/map-pack/pack.mjs <карта> …`) | `await loadPack(core, pack)` |
| много матчей | `tools/node/mass_run.js <core.js> --matches=… --threads=N` | у каждого потока своё ядро и состояние |

Один загруженный экземпляр ядра — одна симуляция (глобальное состояние); параллельно — отдельные потоки / процессы.

## Вход — `runMatch(cfg)`
| поле | тип | что | сейчас |
|---|---|---|---|
| `match` | целое ≥ 1 | номер матча: зерно случайности матча, расписание, профили | есть |
| `maxTicks` | целое | предел тиков (по умолчанию 400 000) | есть |
| `onTick` | функция(tick) | вызывается после каждого тика (только чтение; запись в состояние — нарушение контракта) | есть |
| карта | — | задаётся сборкой ядра или пакетом `.simmap` | есть |
| состав | `{T, CT}`: команды, игроки (ник, профиль: прицел, реакция, роль) | **нет**: составы — в коде (`engine/team/rosters.js`, `LINEUP`, `SIDE_TEAM`); принимать свой состав — изменение игры, после Р8 |
| настройки | баланс, длительность раунда | **нет** (значения по умолчанию игры) |

## Выход
```
{ match, ticks, finished,               // номер; сыграно тиков; матч дошёл до конца (false — упёрся в maxTicks)
  score: {T, CT},                       // победы сторон по раундам (из rounds)
  rounds: [{round, tick, winner, reason, bomb}],   // конец каждого раунда: победитель T / CT, причина (elim / bomb / defuse / time), состояние бомбы
  kills:  [{tick, round, att, vic, weapon, hs}],   // убийства: кто (id бота или null), кого, оружие, в голову
  nades:  [{tick, round, bot, type}] }  // брошенные гранаты
```
`score` считается по сторонам T / CT в момент раунда (стороны меняются в середине матча, `SIDE_TEAM`); команда по раунду — по `SIDE_TEAM`.

## События и запись
- События — подписка `simEvOn(имя, fn(фаза, аргументы, результат))` (Р0.4, только чтение): `endRound`, `feedKill`, `throwNade`, `setPost`,
  `applyDamage`, `tryShoot`, `voiceFeed` и др. (`engine/match/journal.js`). Подписчик не пишет в состояние игры.
- Запись матча для повтора — снимок (`mkSnapshot` / `mkPack`, `src/snapshot.js`) в любой тик; отметки v2 — `node tools/sim.js mark` (Р5.7).
- Причинный след решений (Р3.3, `DLOG`) — вне состояния: включение не меняет игру.

## Гарантии
- **Детерминизм:** одинаковые сборка (или ядро + пакет), номер матча и среда → одинаковый матч бит в бит (Э1 / Э2; `dmath` — одинаковая
  математика в Node и браузерах, Р2). Параллельный запуск = по одному (Р5.8, `mass_run.js --check`).
- **Без знания лишнего:** решения ботов не читают истину врага (сборка; 13 известных исключений до Р8 — `rebuild/TRUTH_EXCEPTIONS.md`).
- **Версия:** контракт — v1 (26.11); поля только добавляются; изменение смысла поля — новая версия.

## Не входит (сейчас)
Свой состав и настройки (см. вход), матч с середины по чужому снимку как API, потоковая выдача событий во время матча (есть только
`onTick` + подписка в том же потоке), сеть / сервер.
