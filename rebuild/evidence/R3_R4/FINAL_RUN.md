## Что подтверждено по владельцам полей

Сборка проверяет `heardSound` и `lastIntel` по имени свойства, независимо от имени объекта. Записи разрешены из перечисленных функций
`engine/know/knowledge.js`. Проверены прямой алиас, строковый индекс, вложенное поле, `Reflect.set`, `Object.assign` и `delete`.
В пробах функция сначала добавлялась в реестр писателей, чтобы проверялось именно владение каналом. Все шесть проб остановлены.
Запись признака приземления перенесена внутрь `knowHear`, сразу после прежнего выбора звука. Вариант с устоявшимся близким звуком
по-прежнему меняет тот объект, который вернул `hearReal`. Локатор на обеих картах подтвердил равенство с предыдущей сборкой до тика
4096 матча 3. [Пробы](knowledge_owner_probes.json) · [локатор](knowledge_owner_compare.json).

[Сверены все 130 полей](multi_writer_review.csv) из списка `v637a`. Для каждого указан исходный писатель, место в коде и роль записи
в живом тике, другом режиме или на границе раунда. В таблице «граница» включает закупку, инициализацию и перестройку карты.
Первоначальный критерий Р3.2 требует явного владельца живого поля и проверки сборкой, которая отклоняет чужую запись.

| Результат сверки | Полей |

Подтверждённые примеры из первой группы — `_flee` (бомба и post-plant T), `_contact` (контакт и бой), `_probeLock`
(разведка, бой, контакт и звук), `_stopWhy` (ход и отдельная ветка тика). Разрешённые исключения Р8 не распространяются
на эти поля. Назначать им владельцев по принципу «разрешить всех существующих писателей» было бы недостаточно для критерия.

## Инструменты и запись метрик

Пройдены сборки двух карт, основной набор проверок, открытие и история отметки, кадры и видео, подстановка браузерного экспорта
на контрольном JSON, профили кадра и тика, снимок трансляции и карты. Проверка профилировщиков здесь касается их запуска и формата
выхода. Данные профилей не входят в приёмочное задание. Прежние прогоны инвариантов, Rust, `why` и сцены переиспользованы.
[Ведомость инструментов](tools_followup.txt).

Запись законченного матча теперь завершается до `matchBegin` следующего матча. Прежний порядок восстанавливал `PROB` из снимка загрузки
до чтения отчёта, поэтому мог отдать ноль событий и потерять причины. Проба в Chromium воспроизводит сброс на штатном переходе матчей
и подтверждает сохранение причины, события и номера эпизода после исправления. [Проба границы матча](rec_boundary.json).

## Выгрузка 334 с ПК

Запустить в PowerShell на компьютере с раннером. Команда только считывает рабочий каталог и кэш. Она упаковывает Chromium-отпечатки
и записи сторожей Р3/Р4. Сохранённая часть `danger` извлекается и в тех записях, где `PROB` уже потерян.

```powershell
$accept334 = Join-Path $env:TEMP ('simcs2-r34-' + [guid]::NewGuid().ToString('N'))
git clone --depth 1 --filter=blob:none --sparse --branch codex/r3-r4-final-acceptance https://github.com/xa11mono/sim-cs2.git $accept334
if ($LASTEXITCODE) { throw 'Не удалось скачать ветку приёмки' }
git -C $accept334 sparse-checkout set --no-cone /rebuild/evidence/R3_R4/ /tools/measure/fingerprint.js /src/q.js
if ($LASTEXITCODE) { throw 'Не удалось получить файлы восстановления' }
$archive334 = Join-Path $env:USERPROFILE ('simcs2-334-r34-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.zip')
python (Join-Path $accept334 'rebuild/evidence/R3_R4/recover_334.py') --r34-only --runner-root 'C:\actions-runner\_work\sim-cs2\sim-cs2' --runner-home 'C:\Windows\System32\config\systemprofile' --runner-home $env:USERPROFILE --out $archive334
if ($LASTEXITCODE) { throw 'Архив не создан' }
```

Прикрепить выведенный в консоли ZIP **к сообщению в этом чате**. Репозиторий для передачи записей не нужен. До выгрузки не стоит запускать
задание, которое очистит рабочую папку раннера. Кэш отпечатков хранится отдельно. Полные файлы 334 пока недоступны, поэтому точный набор
пропущенных номеров ещё не рассчитан.

## Минимальное задание ПК

Генератор получает архив 334 и полный SHA приёмочной ветки. Он проверяет SHA-256, соответствие запросу 334, результат сторожа, среду
и соответствие отпечатков эталону Р2. У пригодных записей проверяет события и причины. При несовпадении отпечатка останавливается,
чтобы расхождение было разобрано до раунда и тика. Если архив потерял только `PROB`, генератор назначает недостающую запись
и сохраняет старый `danger` для независимой сверки.

```sh
python rebuild/evidence/R3_R4/acceptance_334.py --archive /path/to/recovery.zip --ref "$(git rev-parse HEAD)" --out request.json
```

| Задание | Новый запуск |
|---|---|
| Э1 со следом | Недостающие или несовместимые Chromium-отпечатки Ancient и Mirage |
| Э1 с выключенным следом | 8 матчей на каждой карте, вариант `trace: false` |
| Р3.6 | Только номера без пригодной полной записи, 8 на карту с учётом 334 |

Номера взяты из утверждённого набора: 3, 7, 11, 13, 17, 19, 23, 29. Сохраняется `resume: true`. При наличии совместимых результатов
раннер проверяет среду до запуска игр. Задание содержит только `fp` и `rec`. Замеры Р5 отсутствуют. Для проверки итогов экспортировать
каталог результатов с `request.json` и передать той же команде `--verify <каталог>` вместо `--out request.json`.
Код возврата подтверждает Э1, пары со следом вкл/выкл, полноту событий и совпадение восстановленного `danger` на тех же матчах.
Отправка задания на ПК ожидает архива и согласования тяжёлого прогона.
