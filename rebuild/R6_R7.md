# Р6 (скорость на TypeScript) и Р7 (Rust-ядра) — итог (27.11.2026, ветка v640a)

Правило этапов (MASTER_PLAN): игра не меняется (Э2 / локатор / отпечатки), оптимизация принимается только с выигрышем больше разброса
повторов; Rust — только при доказанной пользе в целевом сценарии с ценой передачи данных, иначе TypeScript с записанной причиной.

## Р6 — обязательное: рост памяти Ancient и освобождение между матчами

**Что росло** (Node, ядро v639a, Ancient м3; обход графа объектов каждой общей переменной реестра и полей `M3`): почти весь рост —
`M3.nTriPl`, ленивый кэш плоскостей треугольников для траекторий гранат (`engine/map/geometry3d.js m3TriPl`): ~91 тыс. записей к 20 000
тикам, 449 тыс. к концу матча; ограничен числом треугольников, но между матчами не освобождался. Остальные кэши — единицы МБ и
ограничены сами (`WPM` сбрасывается, `PATHQ` — очистка по числу записей).

**Исправление** (`m3MatchRelease`, вызов в `matchBegin`): ленивые плоскости (`nTriPl`, `nHullPl`) — ответ функции от неизменяемой
геометрии — освобождаются в начале матча; следующий вопрос считает то же число заново.

| куча V8 после сборки мусора, МБ (Node, Ancient, `--expose-gc`) | до (v639a) | после (v640a) |
|---|---:|---:|
| после загрузки | 99 | 99 |
| после матча 3 | 431 | 116 |
| после нового матча (`freshMatch(7)`) | 430 | 120 |
| после матча 7 | 517 | 118 |

Итоги матчей те же (м3: 149 003 тика, 8 : 15; м7: 158 666 тиков, 11 : 13, 160 убийств); локатор v640a = v639a — Mirage м3 и Ancient м7
до тика 15 040 без расхождений. Остаток над уровнем загрузки (+17–21 МБ) — ограниченные кэши путей. Замеры и скрипты — `rebuild/evidence/R6/` (`r6_memory_speed.json`, `memgrow2.js`, `memgrow3.js`, `memrel.js`, `ab.js`, `castrep.js`). На ПК — задание Р8 (`prof`: память
0 / 20 000 / 40 000 тиков страницы, как база Р0.11).

## Р6 — кандидаты скорости (К-1…К-10), проверенные замером

Профиль тика (Node, Ancient м3, 20 000 тиков, собственное время): `m3Cast` 14,3 %, `relax` 12,1 %, анонимные 11,6 %, `zoneDijkstra` 6,9 %,
сборщик мусора 6,7 %, `m3SegTri` 4,2 %, `buildWaypointPath0` 4,0 %, `m3NadeTrace` 4,0 %.

| кандидат | замер | решение |
|---|---|---|
| К-1 куча поиска пути без объекта на вставку (параллельные массивы, тот же порядок) | 3 + 3 попеременно, Ancient м3 20 000 тиков: 5,48 / 5,39 / 5,47 против 5,63 / 5,55 / 5,39 мс на тик; хэш тот же | **не принят** — выигрыша сверх разброса нет; возвращена прежняя |
| К-2 память «линия в этом тике» для `m3Cast` | повторов с теми же аргументами в тике — 14 % из 252 вызовов на тик (Ancient, тики 2000–6000) | **не принят** — потолок < 2 % тика минус цена ключа |
| К-10 рост памяти | см. выше | **принят** (обязательное) |
| передача кадров Worker → страница (Р5) | кадр без кэшей 0,34–0,41 МБ вместо ~17 МБ; переносимый `ArrayBuffer` | принят в Р5; замер мс / кадр в трёх движках — задание Р8 (`wkm`) |

Дальше скорость не трогается: остальные кандидаты К-1 (плотные массивы поиска) требуют переделки с сохранением порядка обхода, а куча —
его часть — выигрыша не дала; правило этапа — без бесконечной оптимизации.

## Р7 — Rust-ядра: решение по каждому кандидату

**Идентичность отдельных вычислений** (корпус Codex `codex/r7-kernel-corpus`, снят с текущего движка v640a, обе карты, по 72 запроса
`knownSegCost` / `m3SegTri` / `m3BoxPlanes`): нативный Rust и WASM — **144 из 144 бит в бит** (`rebuild/evidence/R7/corpus_v640a.json`).

| кандидат | доля в тике (профиль выше) | замер переноса (stage3 bench, те же порты) | решение |
|---|---:|---|---|
| путь: `zoneDijkstra` + `knownSegCost` | ~19 % | на запрос: TS-массивы 302 мкс, Rust нативно 141, WASM 245–262; вызов JS → WASM 0,68 мкс | **TS.** В странице (WASM) выигрыш против TS-массивов 1,2× на ~19 % тика — меньше 4 %; в Node (N-API) до ~2× на путь, ≈ 10 % тика массовой симуляции — при переносе всего поиска с порядком обхода и правилом равенства, с передачей знания команды и огня на каждый запрос. Доказанной пользы в целевом сценарии сейчас нет; первым шагом — TS (плотные массивы К-1), как и записано в плане производительности |
| лучи: `m3Cast` / `m3SegTri` | ~18 % | отрезок × треугольник: JS 45,7 нс, Rust 33,1, WASM 29,4; пересечение границы 680 нс на вызов | **TS.** Пер-вызовной перенос медленнее (граница ≫ вычисление); перенос всего `m3Cast` требует копии геометрии в память WASM (Ancient — сотни МБ) — 1,4× на ~18 % ≈ 5 % тика ценой памяти |
| полёт гранаты: `nadeLaunch` / `nadeStep` (`m3NadeTrace`) | ~4 % | — | **TS** — доля мала |
| прострелы и граф при загрузке (`computeZoneDanger`, `rebuildNav`) | загрузка, не тик | — | **TS** — лучшее средство — кэш тяжёлой загрузки в пакете карты (Р6), не перенос |

N-API и WASM из одного исходника, сборка на Windows, автономный HTML с WASM — не требуются: ни один кандидат не принят. Корпус и ядро
остаются инструментом проверки (`tools/r7-corpus`, ветка Codex).
