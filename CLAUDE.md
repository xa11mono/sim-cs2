## Только для Claude Code
- Субагенты — только свои из `.claude/agents/` (тактик `cs2-tactical-analyst`, аудитор связей `logic-auditor`, аудитор чисел
  `numeric-auditor`, контрсценарии `adversarial-qa`; владелец 22.11) и только с предупреждением владельцу перед запуском («запускаю X:
  зачем»). Остальные (Explore, general-purpose) — только по прямой просьбе. Код правлю я сам, агенты код не меняют. Каждый запуск — с нуля
  и дорого: давать агенту готовые файлы / строки, а не «разберись».
- MCP codebase-memory в облаке не использовать (индексирует папку на компьютере владельца).
- **Долгие команды в облаке** (владелец 26.11, «Stops in 20m»): срок есть у самих инструментов сессии, не у проекта — фоновая команда
  Bash по умолчанию 30 мин (параметр `timeout` — до 2 ч), наблюдатель Monitor — не больше 30 мин; срок задаётся при запуске и потом не
  меняется. Поэтому проверку дольше нескольких минут запускать отвязанным процессом с журналом (`(команда > журнал 2>&1; echo rc=$? >>
  журнал) &`), а Monitor — только как наблюдатель журнала. Истечение таймера Monitor — не конец задачи и не зависание: прогон идёт —
  новый Monitor (или Bash `run_in_background` с ожиданием `until <условие конца>` и `timeout` до 2 ч), до фактического конца прогона и
  разбора результатов. Прогон из-за истечения наблюдателя не перезапускать и не снимать, накопленное не терять. Ожидать одним длинным
  наблюдателем с редким опросом файла (секунды, без обращений к модели), а не частыми короткими проверками — каждое пробуждение тратит
  лимит подписки. Зависание определять по прогрессу в журнале (тики, строки), а не по времени. Прогоны ПК этим сроком не ограничены (задание GitHub — 600 мин;
  матч — сторож `tools/measure/procguard.py`).
- Файлы владельцу (видео «было / стало», отчёты) — `SendUserFile`; страницы — инструмент Artifact (публиковать — только по просьбе, §9).
