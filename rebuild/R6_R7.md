## Р7 — Rust-ядра: решение по каждому кандидату (пересмотр 27.11 — прежний отказ v640a снят)

Прежний отказ (v640a) опирался на перенос отдельных функций с пересечением границы на каждом вызове. Пересмотр — **полные ядра**: одна
библиотека `tools/r7/kernels` (Rust) — луч (`m3Cast` целиком: столбики, корзины, треугольники, блоки, укрытия), поиск пути
(`zoneDijkstra` целиком: цена перехода, сторона CT, места врагов по знанию с `knownSegCost`, огонь, куча с тем же порядком вставок,
продолжение поиска в тике, ближайший участок в порядке ключей объекта JS), трасса гранаты (`m3NadeTrace`). Геометрия и граф передаются
один раз; запрос — числами; ответ — в общий буфер. Сборка — WASM (`wasm32-unknown-unknown`, без bindgen) и N-API (Node) из одного исходника. Математика ядер — только сложение, умножение, деление и `sqrt` (точные по IEEE в любой среде) и `hypot` по алгоритму V8 (как `DM.hypot`); трансцендентных функций нет.

**Корпус реальных запросов — каждый ответ бит в бит** (режим сверки: на каждом запросе матча считают ядро и эталон, сравниваются биты
чисел, ключи и их порядок, типы):

| среда | Ancient | Mirage | расхождений |
|---|---|---|---:|
| Node, облако (N-API и WASM), 15 040 тиков | м7: 3,6 млн лучей, 36 тыс. поисков | м3: 5,5 млн лучей, 59 тыс. поисков | 0 |
| Node, ПК Windows (N-API и WASM), 15 040 тиков, ПК 343 | 3,9 млн лучей, 40 тыс. поисков, 3,4 млн трасс гранат | 5,5 млн лучей, 59 тыс. поисков, 10,4 млн трасс гранат | 0 |
| страница: Chromium, Firefox, WebKit (WASM), 6000 тиков, ПК 343 | 1,4 млн лучей, 13,5 тыс. поисков, 0,9 млн трасс; хэш итога один во всех трёх | 1,9 млн / 19 тыс. / 2,6 млн; хэш один | 0 |

Вклад каждого ядра (Node облако, N-API, по одному ядру, 3 повтора попеременно; `q27/proto_r7_*.jsonl`): путь — Ancient 5,15–5,29 → 4,10–4,13,
Mirage 7,05–8,12 → 4,69–4,82 (сверх разброса); луч — Ancient → 4,98–5,06 (сверх разброса), Mirage → 6,97–7,92 (в разбросе); граната —

| кандидат | решение |
|---|---|
| путь `zoneDijkstra` + `knownSegCost` | **принят** — WASM в игре (страница, Worker, Node) |
| луч `m3Cast` / `m3SegTri` | **принят** — WASM в игре (выигрыш сверх разброса на Ancient; на Mirage не хуже) |
| полёт гранаты `m3NadeTrace` | **оставлен на TS**: отдельно выигрыш в разбросе на обеих картах; ядро и сверка остаются в библиотеке |
| прострелы при загрузке `computeZoneDanger` | **оставлен на TS**: 333 мс JS → 303 (WASM) / 262 (N-API), но передача геометрии 517 / 252 мс — дороже выигрыша |
| граф при загрузке `rebuildNav` | **оставлен на TS**: 0,24–0,39 с, лучи в нём — малая доля (замер профиля) |
| N-API для Node | **не принят**: WASM в Node не медленнее (ПК: быстрее на 4–7 %), одна сборка на все среды, без нативной библиотеки на машину |

**Как встроено** (`engine/map/geometry3d.js`, `engine/nav/path-search.js`): `m3Cast` и `zoneDijkstra` остались хозяевами и зовут ядро;
эталон — `m3CastTS`, `zoneDijkstraTS` (прежние тела). Режим `r7Mode`: `speed` — отвечает ядро (по умолчанию); `shadow` — считают оба,
игра идёт по эталону, расхождения — `R7.bad` (проверка Э2 в любой среде); `ts` — только эталон (временный переключатель этапа; среда без
WebAssembly — он же). Ядро подключается в конце загрузки (`coreLoadEnd` → `r7Start`). Память поиска пути в ядре живёт по правилу `ZDJ`
(тот же тик, матч, граф), граф перезагружается и при изменении на месте (`navUnlinkBlocked`, `mkGraphTo`). Байты WASM — собранный файл
`tools/r7/kernels/wasm/sim_r7_kernels.wasm` в git, сборка вставляет его в страницу и ядро (`src/gamesrc.py`); воспроизводимость сборки —
задание ПК `r7` (sha256 сборки на ПК против файла в git).

(`rebuild/evidence/R7/div_*`); Node: Mirage м3, 3000 тиков, 1,15 млн сверок — 0 расхождений, хэш ts = shadow = speed. ПК 344 (Э1 8 + 8,
воспроизводимость WASM, сверка в трёх браузерах, Worker, массовый прогон, профиль) — **@@PC344@@**.
