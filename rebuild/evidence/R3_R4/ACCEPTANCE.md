### Блокирующие проверки

- **Р3.2, владение.** Сборка `v637a` пропускает `function r3Probe(player){ player.heardSound = null; }`, хотя аналогичная запись через `b` отклоняется. У штатных `knowSound(o,s)` и `knowIntel(o,I)` проверка печатает 0 распознанных писателей для этих полей. В `moveSoundEmit` есть вложенная запись `listener.heardSound.land` вне владельца знания. 130 полей с несколькими файлами-писателями остаются предметом критерия владения. Исторический список писателей и ограничение их прироста сами по себе этот критерий не закрывают.
- **Р3.3, след.** На неизменяемой сборке Mirage, м3, первый тик расхождения со следом вкл/выкл — 2624. Отличается только `PROB`: у CT3 пропадает блокировка `anchor` задачей `ambush`, причина и эпизод. `probTick` читал данные, которые `dlog` переставал писать. В ветке приёмки два ограниченных входных журнала `PROB` отделены от флага показа следа. При включении `why` использует те же записи без второй копии. На м3 Ancient и Mirage локатор подтвердил равенство до тика 3008 как вкл/выкл, так и относительно исходной сборки со следом. Полный Э1 вкл/выкл на обеих картах остаётся обязательным. [Первое расхождение](trace_baseline_mirage.json) · [повторная проверка](trace_followup.json).
- **Р3.6, записи.** Матчевая сверка 8+8 с новыми счётчиками требует полных `rec` и сверки количества событий с причинами. А/B и старые пробы подтверждают описанные случаи, а не всю выборку 8+8.
- **Р4, инструменты и финальная эквивалентность.** Основные пути запуска проверены, индивидуальные проверки всех действующих инструментов документально не закрыты. Э1 последних делений файлов `tick` и `draw` требует отпечатков финальной сборки. Предыдущие проверки 325–331 и записи 332 повторять не нужно.

Согласованные исключения остаются в силе: 13 чтений скрытой информации до Р8 (вопрос 14), поведенческие исправления
124 классифицированных мест до окончания Р8 (вопрос 16), два пересчёта откатов после Р8 (вопрос 17).
`throw.js` и `fight.js` привязаны к шагу модулей Worker Р5.2. Исключения не распространяются на выявленные пробелы проверки владельцев.
Поведенческую ошибку `mir_jump360` в ветке приёмки не исправляли.

а наличие и пригодность каждого отпечатка проверяются по файлам. [Аннотации](run_334_actions.json).

У запуска нет артефактов и ветки `pc-results/334`, включая промежуточные ветки. У [333](https://github.com/xa11mono/sim-cs2/tree/pc-results/333)
опубликованы только задание, журнал и окружение Rust. У [332](https://github.com/xa11mono/sim-cs2/tree/pc-results/332) повторно проверены
25 готовых отпечатков; они относятся к v636a и к заданиям Р5. [Состав 332](archive_332.json).

**Публикация.** На 334 список выгружаемых типов в `publish_results.py` пропускал `rec`.
Из-за этого записи сторожей не попали бы в ветку даже при успешном push. Включение `rec` проверено локальной выгрузкой
с подменой вызова Git. Причина кода 1 шага публикации остаётся неподтверждённой: публичные аннотации содержат только exit code,
а API выдачи полных логов не вернул содержимое. Утверждать, что шаг упал из-за размера, токена или отсутствия `rec`, по этим данным нельзя.

Сборка в запросе 334 зафиксирована на `06ef1061cb442552e8590bb395cb859f433f961d`. В сравнении каталогов `src`, `engine`, `view`
и `data` с вершиной `v637a` меняется только `engine/match/round.js`: добавлены вход `runMatch` и его два служебных значения.
Браузерные `fingerprint.js` и `rec2.js` идут через `freshMatch` / `stepTick` и `runMatch` не вызывают.
Поэтому браузерные результаты 334 можно переиспользовать при совпадении карты, номера матча, инструментов и среды.
Результаты 334 со следом по умолчанию не заменяют проверку с выключенным следом.

### Команда восстановления на ПК

Запустить в PowerShell на компьютере с раннером. Скрипт читает исходные файлы раннера и его кэш, отбрасывает незаконченные/чужие записи,
пишет инвентарь и SHA-256 в ZIP. Прогон не запускается. После выполнения нужен ZIP, выведенный командой.

```powershell
$accept334 = Join-Path $env:TEMP ('simcs2-recovery-334-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
git clone --depth 1 --filter=blob:none --sparse --branch codex/r3-r4-final-acceptance https://github.com/xa11mono/sim-cs2.git $accept334
if ($LASTEXITCODE -ne 0) { throw 'Не удалось скачать ветку приёмки' }
git -C $accept334 sparse-checkout set --no-cone /rebuild/evidence/R3_R4/ /tools/measure/fingerprint.js /tools/node/core_run.js /src/q.js
if ($LASTEXITCODE -ne 0) { throw 'Не удалось получить файлы восстановления' }
$archive334 = Join-Path $env:USERPROFILE ('simcs2-334-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.zip')
python (Join-Path $accept334 'rebuild/evidence/R3_R4/recover_334.py') --runner-root 'C:\actions-runner\_work\sim-cs2\sim-cs2' --runner-home 'C:\Windows\System32\config\systemprofile' --runner-home $env:USERPROFILE --out $archive334
if ($LASTEXITCODE -ne 0) { throw 'Архив результатов не создан' }
```

Если владелец может получить полный лог публикации на GitHub, точная команда выгрузки только неуспешного шага:
`gh run view 45824614322 --repo xa11mono/sim-cs2 --job 139925468149 --log-failed`.
