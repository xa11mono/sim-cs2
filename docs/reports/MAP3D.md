# Карта из 3D-геометрии игры — Mirage (М148)

Шаги А1–А2 общего плана (`docs/PLAN.md`, подробно — `docs/tasks/map3d_plan.md`). Игра не менялась.

## А1. Проверка геометрии по демкам (20.10.2026)

**Что проверяли.** Все убийства пулей из 72 демок Mirage (как в `tools/measure/engine/demo_prep.py`: XY — из `player_death`, Z — ближайший
тик того же игрока). Луч от глаз убийцы к телу жертвы по геометрии столкновений игры (`world_physics.npz`: 86 тыс. треугольников +
1933 выпуклых блока, небо не участвует). Ускорение — сетка 64 × 64 ед. по XY, 0,3–0,6 мс на луч (`tools/map3d/raycast.py`).
Приседа в наших демках нет (в тиках нет `ducked`), поэтому два счёта:

- **«стоя»** — глаза Z + 64 → голова (Z + 62) или грудь (Z + 44);
- **«все лучи»** — глаза Z + 64 и Z + 46 → голова, грудь, таз (Z + 30), со сдвигом ±12 ед. вбок (плечи): закрыто, только если закрыты все 18.

### Главные цифры

| что | у про | **геометрия игры** | наш движок (ENGINE_AUDIT, В1) |
|---|---|---|---|
| убийство без прострела, а линия закрыта — **стоя** | 0 % | **6,2 %** (414 из 6702) | **23,4 %** |
| …закрыта **всеми лучами** (присед, таз, плечи) | 0 % | **0,9 %** (59) | — |
| …то же без прыжков | 0 % | 0,8 % | — |
| прострел (penetrated > 0), линия закрыта стоя / всеми лучами | ~100 % | 61 % / 28 % | — |
| обратная: 2 с не стреляли, глядя друг на друга (±15°), а линия есть | ~0 % | **1,0 %** (из 41 874 пар) | 1,6 % (В8) |
| …не глядя друг на друга (выборка 4000) | ~0 % | 0,2 % | — |

**Вывод.** Геометрия из файла игры совпадает с демками: из 6702 настоящих убийств линию закрывает меньше 1 % (против 23,4 % у нынешнего
движка), а «видит сквозь стены» реже, чем движок (1,0 % против 1,6 %; часть этого 1 % — честные «видел, но не стрелял»: далеко,
ослеплён, перезарядка). 6,2 % «стоя» — это убийства из приседа и по низу тела (из-за ящика, бортика) — значит, А5 должна проверять
не одну линию «центр → центр», а голову / грудь / плечи и присед. Прострелы: у 28 % убийств с `penetrated > 0` линия открыта —
пуля пробила, видимо, другого игрока или мелочь, которой нет в геометрии столкновений.

Картинка `docs/reports/map3d/los_overview.png`: слева — 59 «закрыто всеми лучами» (красным) и 358 «только стоя» (жёлтым), справа — прострелы.

### Где закрыто — крупно (что это за геометрия)

59 случаев собираются в 28 мест; 8 главных — `docs/reports/map3d/los_zoom_1…8.png` (слева — сверху, цвет — высота верха; справа — разрез
по лучу: человечки, линия глаз, красным — что закрывает).

|---|---|---|---|---|

| 3 | Window (мид, −1102, −709) | 3 | рама / подоконник окна (сетка 0) | край проёма окна; поза в окне (присед на подоконнике) |

Остальные 20 мест — по одному убийству, почти все — луч по кромке ящика / стены (подъём глаз на 8–16 ед. открывает: 21 из 59).

**Что такое «невидимая стена» в этих данных.** Ни одной точки игрока (1,25 млн положений из демок) внутри выпуклых блоков нет — все блоки
твёрдые для игроков. Значит, места 1 и 6/8 — это либо невидимые стены «только для игроков» (их надо исключить из видимости и пуль), либо
настоящие предметы (ящики, стойки). Ответ даёт А2 — группа столкновений у каждого блока / треугольника.

## А2. Служебная часть файла (KV3) — группы столкновений, материалы, сущности

**Состояние на 20.10: код готов и проверен на образцах, сам файл карты не получен** (`de_mirage.vpk` — у владельца; в репо и Releases его
нет, компьютер владельца не был на связи).

Сделано:
- `tools/map3d/kv3.py` — полный разбор двоичного KV3 v2–v5 (zstd, LZ4 включая цепочку блоков для блобов, без сжатия) по устройству
  ValveResourceFormat (MIT). Проверен на тестовых файлах VRF: 187 блоков разобраны, в т. ч. физика моделей v5 (`wooden_crate_01` —
  блок, материал `woodcrate`, группа `default`), сущности `default_ents_kv3_v4_zstd.vents_c` (2064 сущности).
- `tools/map3d/vpk_physics.py` переписан на этот разбор (вместо поиска блобов по размерам): из `m_parts[].m_rnShape` берутся
  `m_hulls` / `m_meshes` с `m_nCollisionAttributeIndex` и `m_nSurfacePropertyIndex` (у сеток — `m_Materials`, материал по треугольникам),
  `m_collisionAttributes` (группа, «чем является» — `m_InteractAsStrings`, с чем сталкивается) и `m_surfacePropertyHashes`. В
  `world_physics.npz` добавятся: `mesh_attr`, `mesh_surf`, `hull_attr`, `hull_surf`, `attr_json`, `surf_names`; рядом — `phys_attrs.json` (сводка).
  Имена материалов — по хешу MurmurHash2 (как в игре) из списка известных строк (`tools/map3d/known_strings.json`, 8167 имён: VRF + список
  поверхностей CS).
- `tools/map3d/vpk_entities.py` — сущности: спавны T / CT (`info_player_terrorist` / `counterterrorist`), зоны закладки
  (`func_bomb_target` — коробка и многоугольник по физике её модели), зоны закупки → `data/maps/mirage/geom3d/entities.json`.

Осталось, когда будет файл: `python3 tools/map3d/vpk_physics.py de_mirage.vpk mirage` (сверить, что геометрия совпала с прежней бит в бит),
`python3 tools/map3d/vpk_entities.py de_mirage.vpk mirage`, затем повторить А1 с отбором «только стены для пуль» — места 1, 2, 6, 8
должны уйти, если это playerclip / решётки.

### Запасной путь: прострелы по демкам

`tools/map3d/wallbang_demo.py` → `data/maps/mirage/geom3d/wallbang_demo.json`, картинка `docs/reports/map3d/wallbang_demo.png`.
286 убийств с прострелом: у 221 линию закрывает геометрия; толщина пробитого — медиана 6 ед., 90 % — до 24 ед. Главные места:
Shadow (21 + 13 + 6), Triple Box (17 + 10), Default (14), Ticket (13), Firebox (7). Это — проверка для будущих материалов (дерево / металл
тонкие — пробиваются, камень — нет) и запасной список прострелов, если KV3 не поможет.
