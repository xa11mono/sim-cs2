## Коротко для владельца

1. **Выводы DeepSeek в основном верны** (размеры, состав страниц, воспроизводимость сборки, порядок кода по именам файлов, старт упирается
   в навмеш и прострелы, а не в размер). Принимаются: общий движок + пакеты карт, сохранение автономного HTML, `map3d` без base64, `dist/`,
   уборка.
2. **Опровергнуто три вывода.** (а) Навмеш в `Float32/Int16` «с теми же числами» — нет: половина чисел навмеша в 32 бита не помещается
   (11 317 из 22 267 у Ancient). (б) «Граница JS↔WASM дорогая, 1,1 мкс» — пустой вызов стоит 3–7 нс; 1,1 мкс — это сама работа луча.
   (в) «Для Rust Native надо переписать весь интерфейс» — не надо, есть пути без переписывания отрисовки.
3. **Требует выяснения:** 5 из 1200 лучей Mirage у DeepSeek не совпали («известное расхождение») — при переносе это не принимается без
   точной причины; «+188 МБ памяти WASM» — сравнивались разные величины, нужен повторный замер одной величиной.
4. **Главная новая находка — игра зависит от версии браузера.** Функции `Math.sin/cos/atan2/exp/log/pow` в Chromium 158 и в Node 22
   дают разные последние знаки; если подменить их на реализацию с разницей в один последний знак, матч расходится уже в первые 16 тиков.
   Сейчас отпечатки «бит в бит» сравнимы только в одной версии браузера; Node-прогоны не совпадут со страницей; Rust не совпадёт с JS.
5. **Решение — своя общая математика `dmath`** в TypeScript и Rust из одного алгоритма. Проверено: Rust-библиотека `libm` даёт одинаковые
   биты нативно и в WASM. Это **один раз** изменит биты матчей (поэтому нужен ваш ответ), зато потом игра одинакова везде: в браузере,
   в Node, в Rust.
6. **Rust Native — целевое ядро** для пути, лучей, полёта гранат и тяжёлой загрузки, WASM — то же ядро для браузера. Принимается ядро,
   только если каждый его ответ совпадает с TypeScript-эталоном бит в бит и выигрыш больше разброса замеров. Логика ботов остаётся на
   TypeScript: в ней сотни мест, где JS и Rust считают по-разному (округление, NaN, порядок ключей).
7. **Rust Native без переписывания отрисовки:** Node + нативное ядро для массовых матчей; та же страница может смотреть такой матч через
   локальное подключение; при желании — окно-приложение (Electron) с той же страницей.
8. **Автономный HTML сохраняется**: проверено, что один HTML-файл с WASM внутри и фоновым потоком работает из файла. На странице-артефакте
   claude.ai не проверено — нужна ваша разрешённая тестовая страница.
9. **Структура без номеров**: `engine/` (игра) · `kernels/` (Rust) · `view/` (показ) · `maps/` · `tools/`; карта всех 90 файлов готова.
   Переименование — отдельным шагом бит в бит, когда порядок загрузки станет явным.
10. **Отметки для всех агентов**: один файл отметки + текстовый рассказ (для ChatGPT и DeepSeek в чате) + картинка + одна команда.
    **Причинный дебаг**: «след решения» у каждого хозяина — что знал, какие варианты, что отсеяно и чем, что выбрано, ответ арбитра,
    исполнено ли и кто перезаписал; игру не меняет.
11. **Агенты**: один файл правил `AGENTS.md` для всех, `CLAUDE.md` его подключает; Graphify — как навигация, не источник правды;
    принципы Ponytail адаптированы: сначала данные и хозяин решения, потом новый код, но механика чинится во всех местах.
12. **Порядок**: Р0 опора → Р1 TypeScript → Р2 общая математика → Р3 контракты, реестр состояния, след решений → Р4 имена без номеров →
    Р5 симуляция отдельно, Node, пакеты карт, автономные сборки, новые отметки → Р6 скорость → Р7 Rust-ядра → Р8 приёмка.
    **Поведение — только после приёмки.** Статистика матчей больше не доказывает эквивалентность при переносе: любое расхождение
    ищется до конкретной операции.
