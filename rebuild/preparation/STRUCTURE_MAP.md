# Р4. Уточнённая карта переименований

[Карта путей](path_migration.csv) содержит **129** решений, включая **91 файл** `src/game/` в точном порядке исходной склейки. Исходная [карта этапа 4](../../docs/reports/audit_2026-11-24/stage4/STRUCTURE_MAP.md) покрывала 90. В базе уже есть `005_dmath.ts` и `275_look_turn.ts` вместо `275_look_turn.js`. Для всех остальных сохраняется фактическое расширение, даже если старая карта предлагала будущий TS. Имена назначения уникальны также без учёта регистра. Порядковый номер в CSV — индекс текущей сборки, а `legacy_prefix` — идентификатор для переходных проверок/ссылок.

[Реестр потребителей](structure_references.csv) содержит 3 081 совпадение путей, имён, признаков порядка и числовых ссылок. Проверены доступные текстовые файлы `src/`, `tools/`, `.github/`, `rebuild/`, основные инструкции и архитектурное описание. Совпадение числа — кандидат для ручной проверки, а не команда массовой замены. Реестр не заменяет полную проверку с собранной страницей, динамическими путями и историческими материалами.

## Последовательность и автоматическая проверка

1. На принятой базе Р3 перепроверить полноту CSV и список зависимостей. Р4.1 вводит манифест из фактического порядка обеих склеек. Проверка: каждый исходник ровно один раз, нет непредусмотренных префиксов после rename, кандидаты назначения уникальны после casefold и отсутствуют в целевом дереве. Сравнить последовательности blob, в т.ч. модульные и шаблонные. Держать чтение старого layout по ревизии.
2. Р4.2 переносит файлы и обновляет потребителей одной обратимой операцией. Не менять исходные байты игры при rename. Быстрый тест на старом/новом манифесте сравнивает последовательность и хэш содержимого, соответствие `module_source`, построение `__SNAP`, старые идентификаторы `nade_hash`; слот DM остаётся до обёртки. На Windows проверить разделители и имена. Файлы A/архивы проверяются отдельной процедурой, текущие якоря и ссылки тестируются автоматически.
3. Сборочные проверки: `gen_maps --check` и отрицательные примеры для писателя, замка, UI-границы и Math; `sim.js typecheck`; локальная сборка двух карт в согласованной среде; `map_check` с принятыми исключениями. Сравнить отпечатки Э1 с принятой базой, сохранение визуальных и replay entry points. Сравнение HTML учитывать только документированные отличия диагностических путей, идентификатора сборки и выходных путей. Порядок импорта, генерации и чтения данных покрыть отдельными проверками.
4. Р4.3 переводит рабочие выходы в dist с обновлением локаторов, CLI, runbooks, CI и сборки старой ревизии. Проверка явных и дефолтных путей и обеих автономных страниц. Р4.4 — по одному разбиению с Э1. Р4.5 принимает отрицательный тест нового `NNN_*`. Р4.6 проверяет [документацию](DOCUMENTATION.md) и пакет контекста.
5. После каждого шага проверить `git diff --check` и список изменённых путей. Для контроля ссылок извлечь из CSV все перемещённые старые пути, базовые имена и ID, повторно искать в исходниках и конфигурации; сопоставить исключения с историей/переходниками. Проверить существование нового пути для каждого потребителя, относительные Markdown-ссылки и якоря. Перед принятием — ноль новых битых ссылок/путей, а исходные разрывы из A закрыты или явно разрешены владельцем.
