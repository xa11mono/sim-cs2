Основа — главный принцип (начало docs/PRINCIPLES.md): бот знает и делает то,
что может знать и делать настоящий игрок в про-матче. Никаких правил под

сверки. Делать по частям, каждая часть — отдельный чат с планом на согласование
(правило CLAUDE.md). Порядок: A → B1 → B2 → B3 → C; Г и Д — в любой момент
(маленькие, не трогают мозг).

## С. Стрельба (движок; делать до части A)
Сейчас: темп оружия верный (`fireIntervalTicks` из rpm), но ритм рваный —
каждый тик `tryShoot` (15_combat.js) проверяет прицел/«нагрев»/фазу стрейфа и
стреляет, когда всё совпало → 2 пули, пауза, 1, пауза, 3. Трассеры рисуют
каждую пулю с собственной случайной ошибкой — разлёт выглядит случайным.

Сделать как у игрока:
1. **Режим огня — решение бота**, а не результат проверок каждый тик: тап
   (далеко), очередь 2–5 (средне), спрей (близко); по оружию (AWP/SSG — один
   выстрел + затвор, дигл — тап, ПП/винтовки — по дистанции), по ситуации
   (держит угол / выходит / бежит). Внутри очереди — ровно темп оружия; пауза
   между очередями — пока прицел/разброс восстанавливается.
2. **Отдача по рисунку оружия** (`sprayPat`): пуля уходит по рисунку, бот
   компенсирует часть по навыку; трассеры — по реальному направлению пули
   (разлёт видно как рисунок, а не как случайный веер).
3. **Контрстрейф**: остановка → выстрел/очередь → снова шаг; на бегу винтовкой
   не стреляет (уже есть — свести в одно место с режимом огня).
4. **Первый выстрел** точнее при стоящем и наведённом прицеле; перевод на
   второго врага — с задержкой доводки.
5. Убрать старое: «ждать остывания нагрева» (`tapFrom`, `tapK`, `w.spam`),
   отдельные куски стрейф-дуэли, которые решают ритм мимо режима огня.

Сверка с демками (только сверка): data/demos/*_weapon_fire — каждый выстрел
(тик, игрок, оружие). Посчитать у про и у нас: пуль в очереди по дистанции
(≤300 / 300–700 / >700 px), пауза между очередями, время от появления врага до
первого выстрела, доля тапов на дальней дистанции.

## B. Добавить (новый мозг команды)

### B1. Восприятие как у игрока → картина команды
Один модуль `09_knowledge.js` (уже — одно место). Каналы:
- **звук**: шаги (бег/шифт, сколько источников, направление с ошибкой по
  дистанции и стенам), прыжок/приземление, перезарядка, зум AWP, бросок и
  разрыв гранаты, плант/дефуз, подбор оружия. Есть `emitSound`/`hearPos` —
  свести все звуки к ним.
- **глаза**: враг (кто, оружие, HP примерно — по попаданиям), граната в полёте
  и откуда кинута, смок/молотов где горит, бомба на земле/у кого.
- **киллфид**: кто кого, из чего, хедшот, через стену → роль по нику (энтри,
  люркер, AWP — по прошлым раундам этого матча), закуп врага по оружию.
- **время раунда + своя роль** → чего ждать сейчас (тайминги выхода к точкам
  из REACH).
Всё — в общую картину команды (belief по зонам + список известных врагов с
возрастом и точностью). Никаких «знаний» мимо каналов.

### B2. Тимспик
`commSend/commFlush` расширить до сообщений с типами:
- **инфа**: «N на X», «бомба у Y / на земле в Z», «AWP на линии», «ранен»,
  «минус один», «пусто на X», «слышу ротацию».
- **просьба**: «иду X — нужен второй», «держи мой угол», «стяните одного на X»,
  «флешку мне на пик».
- **план IGL**: расстановка/тактика на старте; перестройка по картине и
  времени («никого 30 с — один чекает мид»).
- **ответ**: «иду», «не могу».
Задержка: на речь 0,5–2 с (по длине), услышали все сразу; говорить одновременно
может один (очередь). Бот сам решает, что сказать, — из своей картины и целей
(новое знание, ухожу с угла, нужна помощь), не готовые фразы под случаи.
Реакция — в B3, не отдельными правилами. Текст сообщений — в консоль (В1).

### B3. Картина команды «кто что держит» + выбор действия
- Таблица команды: у каждого — роль, задача, угол/вход, который он держит,
  где он. Обновляется из позиций и тимспика.
- Каждый бот выбирает действие одной оценкой полезности (utility) из целей:
  держать нужный угол, не стоять одному без размена, ответить на просьбу,
  закрыть опустевший угол, играть на бомбу, не умереть зря. Опустевший угол /
  просьбу забирает тот, кому ближе и кто меньше нужен на своём месте.
- Разметка карты (как у ботов CS): точки укрытий у каждого входа, точки
  встречи (откуда появится враг и куда смотреть) — считаются один раз по
  стенам и навмешу.
- Заменяет 32 функции выбора позиции (полный список — docs/archive/AUDIT,
  разделы 1 и 3).

### B4. Префайр
- Держащий: слышит шаги за углом / знает по картине, что сейчас выйдут → ставит
  прицел на край угла на высоте головы, широко или узко по форме угла (точки
  встречи из B3). Реакция быстрее, если прицел уже там (`holdReact`).
- Выходящий: идёт к углу с прицелом на обычные позиции, где его принимают
  (точки укрытий на той стороне), чекает их по очереди, ближние первыми.
- Убрать «префайр по памяти» на каждом шаге (15_combat.js ~22–79, ~295) —
  заменить этим.

### В2. Киллфид (20_hud.js, `feedKill`/`renderFeed`)

`Убийца` + `Ассистент` · [иконка оружия] · [значки] · `Жертва`
- ники цветом своей команды (CT голубой, T жёлто-оранжевый);
- «+ Ассистент» — кто нанёс урон этой жертве (≥40 HP) или ослепил её, не
  убийца; если нет — не показывать (нужно хранить урон по жертве за раунд);
- иконка оружия — белый силуэт (SVG на каждое оружие: AWP, AK, M4A4, M4A1-S,
  FAMAS, Galil, SG, AUG, SSG, MP9, MAC-10, UMP, MP7, P90, пистолеты, нож, HE,
  молотов); нет иконки — короткое название;
- значки после оружия, только если было: через смок, прострел (стену),
  хедшот, ноускоп (AWP/SSG без прицела), убийца ослеплён;
- фон строки полупрозрачный тёмный; своя команда наблюдателя — без рамки.
Образцы: docs/tasks/killfeed_ref1.png, killfeed_ref2.png.
Значки «через смок / прострел / ослеплён / ноускоп» передавать из стрельбы
(15_combat.js) в `feedKill` вместе с hs.
