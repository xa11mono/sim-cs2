# Дуэли, смоки выхода, производительность — ответы нейросети владельца (05.11.2026)

Полный текст — в истории чата 05.11. Суть.

## Общий принцип
Решение — по ситуации, информации бота и риску, не по сценарию роли / тактики. Уровни: восприятие → оценка угрозы → решение → исполнение.
Скрытых координат / HP / оружия врага не использовать. Чисел без данных не вводить (проектные — с пометкой). Логика общая для всех карт,
геометрия — из MAP. Существующее устройство (500 decideAction, 470 fightCycleTick, 350 contactTick, 365/366/390/420 гранаты) сохранять,
улучшать условия решений, не писать отдельный «proBrain».

## Дуэли (Д1/Д5) — ОТЛОЖЕНО (владелец 05.11: «дуэли пока не делаем»)
- Цикл линия → укрытие → снова, PEEK_PRO (92 демки Ancient: dur — окно между первым и последним выстрелом, не время «держать кнопку»;
  пауза 1,1–2,7 с; repeek 24–26 %) — оставить. Менять условия «продолжать ли бой»: HP (50 и 10 — разное), кто получил преимущество, число
  врагов (видимых + свежая инфа), оружие / дистанция, реальная возможность размена (у про при гибели свой ≤ 350 ед. в 71–77 %, у ботов
  38–54 %), ценность позиции / задачи (роль меняет привлекательность, не запрещает).
- Разделить «пик за инфой» и «дуэль»: PROBE → CONTACT → ENGAGE / DISENGAGE (состояния одной системы). Пик становится дуэлью: видит врага и
  может стрелять, по нему стреляют, попали, враг держит его линию, можно добить раненого.
- За укрытием: держать угол / перепик с того же места / с другого — по ситуации, не автоматически. В плечо — полное укрытие, соседняя точка
  с видом целиком (уже так: _shoulderShot, fightBetter).
- Враг в 2–3 м за углом: пик (преимущество оружия, размен, выгодный угол) / держать (враг сам пройдёт контролируемый проход) / граната
  (флешка под свой или тиммейта выход, молотов по известной позиции, HE по точной, смок — разорвать линию и уйти) / отход (мало HP, сильнее
  на дистанции, несколько врагов, нет размена). Граната не вытесняет оружие в упор.

## Смоки выхода (Д4) — общее для всех тактик и карт
- Маршрут группы (позиция → подход → вход → сайт) → позиции CT, с которых он простреливается → оценка каждой: Risk = P(CT там) × Exposure
  (время и сколько своих на линии) × Impact (кроссфаер, AWP, высота, спина) — веса без данных не выдумывать.
- Приоритет: линии на пересечение открытого участка → кроссфаер → сильные одиночные (AWP, высота) → фланг / спина (часто — игрок, не смок).
  Один смок может закрыть несколько линий — считать закрытые угрозы, не позиции.
- Смоков меньше угроз: закрыть то, что нельзя пересечь; кроссфаер; молотов — статичного; флешка — следующий угол; остальное — пик с
  разменом. Не обязательно тратить всё до выхода.
- По тактике: быстрый — критические линии заранее, не терять темп; дефолт — часть на контроль карты, часть на выход; сплит — цели по
  группам, исполнитель должен успевать; фейк — не тратить нужное настоящему выходу; эко-раш — минимум смоков, флешки, размены.
- Смок на свой путь — когда открытый участок простреливается, обход длинный, группа успевает и есть контроль выхода CT из дыма.
- Ждать только критические смоки (EXU уже так: assigned → flying → forming → ready / failed, резерв exuBackup). Критичность (exuCritical)
  сейчас — вид на вход на сайт; развивать: открытые участки пути, кроссфаеры, известные CT.
- Кто кидает — у кого граната, кто ближе, кто успевает, кого нельзя отвлекать (уже так в 365/366/390). Ожидание выхода — каждый свой угол,
  не в одной точке (у про ближе 60 ед. к своему на выходе 11–13 % времени, у ботов 26 %).
- Известные CT (видели / слышали / колл / киллфид) важнее стандартных позиций; старую инфу не тратить автоматически.
- CT: задержка выхода по свежей инфе (ctDelayNade), не бросать всё; занят сайт — сохранить жизнь, ретейк.

## Производительность (Д3)
- Кэшировать расчёты путей для актуального состояния (позиция, точка, команда, граф, огонь, известные враги), не «лучший бросающий =
  id». В lineupTick путь на пару «игрок — точка» — один раз за выбор (сейчас: okBot + cost в сортировке + luSpotFor). Назначенную задачу не
  перебрасывать ближайшему каждый тик; защиту «точка позади» (380 t.int, luBehind) сохранить.
- ZDJ (продолжение Дейкстры в тике) — оставить; долгоживущий кэш расстояний — нельзя.
- Физику гранат не упрощать. Счётчики: cacheHit, guessHit, fullSearch, jumpSearch, wideYawSearch, robustChecks, traceCalls, solveMs по типам.
  Стандартные лайнапы — запечены (guess_bake); пользовательские — при сохранении. Редкий полный поиск — по частям (бот стоит, состояние то
  же). Координаты броска не округлять (380 — точное состояние).
- Не трогать 64 Гц, точность навмеша, число ботов. Дорогие решения ИИ — по событию (смена тактики, новая инфа, смерть, фаза), не каждый
  тик. Отдельно: рисование (620), сборщик мусора, пространственные запросы.
- Порядок: 390 повторные пути → 050 повторное использование Дейкстры → 390 точка группового лайнапа → 380 диагностика подбора → 385 поиск по
  частям → 540 бюджет тика → 620 рисование. Проверка — те же исполнители / точки / броски бит в бит; p95 / p99 / макс тика, число
  zoneDijkstra, полных переборов; на ПК — профиль Chrome (JS / рисование / сборщик мусора).
