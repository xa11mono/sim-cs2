# Передача прототипа универсальных отметок на Р5.7

Прототип работает отдельно от симулятора на Node.js 20+. Он читает пакет, проверяет его целостность, конвертирует доступные старые данные, распаковывает вложения и строит Markdown для Claude Code, Codex, DeepSeek и чата без доступа к репозиторию. Ветка основана на `v599a` (`e1dfdd950dbfb913a4182b9d9432b6341d43d918`).

Основания для формата — Р2.1, Р3.1, Р3.3 и Р5.7 в [MASTER_PLAN.md](../../../rebuild/MASTER_PLAN.md), [АР-12 и АР-13](../../../docs/architecture/DECISIONS.md), [архитектурное дополнение §8–9](../../../docs/reports/audit_2026-11-24/stage4/ARCHITECTURE_ADDENDUM.md) и [аудит хранения диагностических событий](https://github.com/xa11mono/sim-cs2/blob/b54cb4fec77845c4c1fc5aefd38294443473a382/rebuild/diagnostics-audit/STORAGE.md). Старый формат сверялся с `src/marks.js`, `docs/tasks/02-mark-moment.md`, `tools/marks/` и маршрутизацией `tools/sim.js`.

## Запуск

Команды из корня репозитория. Выходные папки `convert` и `unpack` должны быть новыми.

```sh
node tools/marks/prototype/cli.cjs help
node tools/marks/prototype/cli.cjs convert rebuild/scenarios.json mark-demo --scenario=mir_jump360 --pre=tools/marks/snaps/mir_m1794418376570_v559_m3.5s.json.gz
node tools/marks/prototype/cli.cjs open mark-demo
node tools/marks/prototype/cli.cjs check mark-demo
node tools/marks/prototype/cli.cjs unpack mark-demo mark-unpacked
node --test tools/marks/prototype/prototype.test.cjs
```

Для записи из базы браузера передать JSON одной отметки и её локально выгруженные файлы с `--snapshot`, `--pre`, `--image`. ID вложений без файлов остаются ссылками из источника. Для отдельного `mkPack` требуется `--role=moment` или `--role=before`. Оба вида входа читают JSON и JSON.gz. Оригинальные файлы копируются побайтно. `unpack` сохраняет проверяемый пакет и пишет развёрнутый JSON графа для gzip-снимков в `decoded/`. Таблица ссылок сохраняет циклы, алиасы и специальные числа. Декодер также доступен из `mkpack.cjs` для чтения JS-объекта инструментом.

## Контракт пакета

Прототип переносит пакет как папку с `mark.json`, производным `mark.md` и перечисленными вложениями. Внешний архив для выгрузки одной кнопкой остаётся частью Р5.7. Схема манифеста — [mark-v2.schema.json](mark-v2.schema.json). CLI добавляет проверки, которые требуют нескольких объектов или файлов.

| Поле | Смысл |
|---|---|
| `format`, `version` | `sim-cs2/mark`, версия оболочки `2`. Схемы вложений меняются независимо. Неизвестная версия оболочки отклоняется. |
| `identity` | Версия игры, SHA-256 сборки и пакета карты, версия `dmath`, карта, матч, раунд, тик, частота тика и seed. Для воспроизводимости предусмотрены хэши настроек и входной памяти, а также идентификатор профиля среды. Старый `env.src` хранится как короткий отпечаток исходника. |
| `owner`, `source`, `environment` | Слова владельца, ожидаемое действие, пункт, бот, исходный документ и исходные ссылки. Для реестра сохранено его исходное описание, а номер матча и раунда извлекаются из существующей аннотации, когда она имеет известный формат. |
| `snapshots.moment`, `snapshots.before` | Снимки с ролью, тиком и дескриптором формата. `registry` идентифицирует версию реестра после Р3.1. `identity` внутри дескриптора может дополнительно связать этот снимок с заявленными входами. Чекпоинт «до» может быть в предыдущем раунде того же матча. |
| `summary` | Присланная сводка или хэши старой записи. Старые `sees`, `why`, `lookReason` и `log` показываются с указанием происхождения. Поля выбора, знаний и арбитража из них не синтезируются. |
| `trace` | Границы окна по тикам и ссылка на вложение с независимой версией. Структура следа Р3.3 остаётся у его производителя. |
| `image` | Исходный PNG или JPEG. Файлы старых отметок сохраняют формат браузерной выгрузки. |
| `diagnostics` | Отдельный журнал вкладов метрик. У него собственная версия и область покрытия. |

Одинаковый дескриптор вложения содержит `file`, `codec`, `version`, `bytes`, `sha256`. Проверяется SHA-256 записанных байтов, включая gzip-оболочку. Хэш обнаруживает порчу при сохранённом манифесте. Подпись происхождения в прототипе не предусмотрена. Для ссылок допускаются имена файлов внутри пакета, повторные имена и симлинки отклоняются. Кодек `mkpack/1` проверяет граф ссылок и сравнивает доступные координаты момента с манифестом. Для будущего формата снимка проверяются файл и метаданные, а декодирование отмечается как недоступное.

## Проверка совместимости

`node tools/marks/prototype/cli.cjs check mark-demo --expect=target.json` сверяет с профилем запуска. В `target.json` можно указать поля `identity` и поля `snapshotCodec`, `snapshotVersion`, `registry`. Пример частичной сверки — `{"map":"mirage","seed":0}`. Нулевой seed допустим. Число `0` и строка `"0"` имеют разный тип. Отсутствующее значение остаётся неизвестным, включая seed старой отметки.

| Результат | Что проверено |
|---|---|
| `target-not-provided` | Пакет прочитан, профиль запуска отсутствует. |
| `unverified` | Профиль задан, но сверка неполна или декодер снимка пока отсутствует. |
| `metadata-match` | Поля профиля совпали для поддерживаемого формата снимка. Нужны `gameVersion, buildHash, map, mapHash, dmath, seed, tickHz, settingsHash, memoryHash, environmentId, snapshotCodec, snapshotVersion`. |
| Выход 1 | Повреждение, несовпадение заданного значения либо `--require-compatible` при неполной сверке. |

Выход 0 обычного `check` означает, что сохранённое содержимое прошло доступные проверки. Фактический повтор имеет отдельный статус `replay: not-run`. Версию для старой отметки выбирает действующий `tools/marks/mark_build.py` по `env.src`. Проверку воспроизведения выполняет `tools/marks/mark_replay.js` на соответствующей сборке и прежнем входе. Прототип их не запускает.

## Диагностические события

В манифесте `diagnostics.version: 1` описывает одну сессию и один матч. `metrics` задаёт ID, ревизию детектора и единицу. Диапазон `[fromSeq, toSeq)` описывает область записи, например только окно отметки. Каждая часть диапазона покрыта gzip-чанком или явным `gap` с причиной. Чанк хранит раунд, границы seq и тиков, хэш и размер. Тики в пределах матча упорядочены, одно и то же время допускает несколько событий с разным seq.

Запись в чанке — один UTF-8 JSON-объект на строку с LF. Обязательные поля `seq, tick, phase, episode, metric, outcome, delta, reason, sourceEvent, facts`. `reason` — стабильный код причины от детектора, `sourceEvent` — ID записи, породившей вклад. Опциональны `actor, target, checkpoint`. `facts` содержит ссылку `{domain, ref}` с доменом `observation` или `world`, либо `{missing: "причина"}`. Пометка `world` предназначена для разбора после симуляции. Доступность содержимого по ссылке должен обеспечить recorder Р3. Прототип проверяет структуру ссылки и отмечает явно неизвестные факты.

`counted` добавляет вклад к метрике. `eligible`, `excluded` и `censored` фиксируют возможности, исключения и неполные наблюдения. Положительный целый `delta` принадлежит одному событию. Идентификатор эпизода позволяет получить все записи эпизода и сохранить отдельно объём счётчика и число разных происшествий. Два seq с одним episode могут быть двумя законными вкладами. Двойное срабатывание детектора для одной причины разбирается по единице, исходу и `sourceEvent`. Инструмент не удаляет такие записи автоматически.

`summary` содержит итоговые числа каждого исхода по метрикам. CLI в потоке заново считает суммы. Полный диапазон должен совпасть с `summary`. При явной потере сохранённая сумма служит нижней границей, а отсутствующие причины остаются неизвестными. Недекларированный пропуск, повтор seq, неверные границы, нарушенный порядок и неверная контрольная сумма завершают проверку ошибкой. Команда `events` выдаёт все сохранённые записи в JSONL и принимает фильтры `--metric`, `--episode`, `--round`. Её вывод включает сессию, матч и раунд.

При внедрении запись создавать у владельца решения коротким payload. Передавать блоки за пределы тика и там сериализовать, сжимать и сохранять. Полный поток и выборка для UI имеют разные назначения. Прототип при чтении держит только текущую строку, буферы потока, манифест и суммы по метрикам. Снимки разбираются отдельной операцией целиком. Лимиты чтения прототипа — 128 МиБ на отдельный JSON или вложение вне диагностического потока и 1 МиБ на строку JSONL. Это лимиты инструмента. Размер чанков, очередь записи и возможный внешний индекс эпизодов определить по измерениям Р5.8. Формата для сжатия повторных вкладов пока нет, поэтому для любого сохранённого seq доступна собственная запись.

Ограничения из аудита сохраняются при миграции. Для Ancient после dmath, матч 3, показатель `stall=118` подтверждён итогом, но сохранилось 40 строк, остальные 78 причин недоступны. Известные повторные инкременты `stall` и I-25 и пропуски I-09 после заполнения старого буфера требуют работы с детекторами Р3. Конвертер не восстанавливает их и не переносит старую выборку в новый полный журнал.

| Источник | Результат |
|---|---|
| `mir_jump360`, Mirage | Отметка на тике **69014**, сохранённый чекпоинт на **68790**, матч 3, раунд 12. Конвертация, проверка SHA-256 и распаковка прошли. Развёрнутый JSON совпал с исходной распаковкой gzip побайтно. |
| `mir_stuck_window`, Mirage | Отметка на тике **62402**, сохранённый чекпоинт на **61440**, матч 3, раунд 11. Те же проверки прошли. |
| `rebuild/evidence/R2/r2.1_test_mark.json` | Матч 3, тик **2224**, ссылка на чекпоинт **2000**, короткий отпечаток исходника `0d4686fe73618d98`. Прочитаны 648 числовых хэшей, исходный файл сохранён побайтно. В репозитории рядом с этим файлом нет соответствующего `pre.json`. |

Чекпоинты из реестра не содержат снимков момента отметки. Исходные экспорты владельца с вложениями в текущем checkout не найдены. Формат старой браузерной записи проверен тестовой записью со ссылками и сохранёнными наблюдениями. Тесты также покрывают неполный манифест, повреждённый JSON и gzip, битую ссылку графа, неподдерживаемые версии, расхождения карты, seed, тиков и сборки, 408 диагностических записей через границу раунда, объявленные потери и неверный итог. Все изменения находятся в `tools/marks/prototype/`. Проверки выполнены на записанных файлах и локальных тестовых данных.

## Внедрение после Р3

1. Подключить адаптер реестра Р3.1 к дескриптору снимка. Версию реестра и допустимые миграции должен объявлять производитель. Подключить проверку профиля запуска к настоящим хэшам карты, сборки, настроек и памяти.
2. Подключить отрисовку причинного следа Р3.3 в Markdown. Использовать записанные варианты, знания, ответ арбитра, исполнение и перезапись. Сохранить признак неполного окна.
3. Подключить запись атомарных вкладов к подписке Р0.4 и отделить её от UI-выборки. Измерить время тика, память и очередь в целевых средах. Сверить инкременты и знаменатели, проверить ложные срабатывания на парах из аудита.
4. Подключить экспорт одним файлом, команды Р5.7 через `tools/sim.js` и официальный путь выбора старой сборки. На обеих картах проверить реестр, фактический replay и совместимость в целевых средах. До этого статус `metadata-match` подтверждает сравнение полей, а не повтор матча.
