# План: бросок смока с разбега / на ходу (Run-up Throw) — 30.10.2026

## Зачем
Все лайнапы смоков, которые у нас летят дольше 8,1 с (99-й процентиль про), — Ancient 5, Mirage 9 (`tools/nades/smoke_long.js`, v486), —
имеют у про быстрый бросок, который наша физика кладёт ≤ 32 ед. от цели. Почти все такие броски про — на ходу или в прыжке
(Mirage «Stairs (сетап)»: 104 броска, все на ходу, медиана 2,45 с; у нас стоя — 8,1–8,7 с). Бот кидает лайнап только стоя
(`380`: `NADE_STILL_V` — сначала остановиться), механизма броска на ходу нет (ссылка на `nadeRecTick` в `385` — устарела).
Физику не меняем: она повторяет броски про (медиана времени совпадает, `check.js`).

## Что есть в данных (проверено: `data/maps/<карта>/throws.json`, смоки)
| поле | есть | что даёт |
|---|---|---|
| `pos` (ноги), `yaw`, `pitch`, `duck` | у всех (Mirage 11 095, Ancient 11 303) | точка и прицел броска; присед — 36 / 11 бросков |
| `vel` [vx, vy, vz], `hspeed`, `move` | у всех: stand 5111 / 3705, walk 2523 / 3043, run 1477 / 1513, jump 1984 / 3042 | скорость и вид движения **в тик броска** |
| `strength`, `jumpBind` | у ≈ 1/3 (подобраны `check.js --fill` по точке разрыва) | сила (ЛКМ / обе / ПКМ) и прыжок на бинде |
| `det` (точка, время) | у всех | проверка: куда и когда должен лечь |
| начало разбега, путь до броска | **нет** | направление разбега = направление `vel`; длина — из разгона (ниже) |

## Устройство (одно место — `380` лайнап, физика — `385` без изменений)
1. **Запись лайнапа (бейк, `tools/lineups.py` / `cluster.py`):** для лайнапа брать «эталонный бросок» — медиану группы бросков про с тем же
   видом движения, у которых наша физика кладёт ≤ 32 ед. (`check.js`): `{yaw, pitch, strength, jumpBind, duck, vel, move}`. Нет такого —
   лайнап без разбега (как сейчас).
2. **Подход:** точка старта = точка броска − `vel`/|`vel`| × L, где L — путь разгона до |`vel`| при ускорении движка ботов (`SPEED`, разгон
   из `540`; посчитать, не придумывать). Бот идёт на старт (пост `lineup`), разворачивается по `yaw` эталона.
3. **Выполнение:** с заданием «разбег» бот бежит по прямой к точке броска; в тик, когда он ближе 1 тика хода к точке и его скорость
   (`nadeBotVel`) в пределах ±10 % от эталона, — бросок: подбор `nadeSolve` с **фактической** скоростью (как сейчас для своих гранат) и
   `guess` = эталон (локальное уточнение, дёшево). Прыжок на бинде — `jump: true` в вылете (`385` уже умеет).
4. **Сорвалось** (помешали, контакт, свой на линии): задание назад на старт, один повтор; потом — бросок стоя (как сейчас) или отказ.
5. **Команда:** время срабатывания знает `366` (`n.etaDet`) — синхронизация выхода не меняется.

## Риски
- Разбег через людей / в узком месте — бот не наберёт скорость: срыв → бросок стоя (п. 4).
- Подбор на ходу дороже (кэш по точному состоянию не срабатывает): только локальное уточнение у эталона.
- Длина разгона — по движку ботов, а не CS2: если разгон ботов не как в CS2, скорость в тик броска не та — проверять по `vel`.
