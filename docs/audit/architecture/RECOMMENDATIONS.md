# Рекомендации (v598, 24.11.2026)

Итог аудита. Ничего из этого не начинать без утверждения архитектуры владельцем. Рабочая игра, боты, механики,
тактики, физика, числа, вид и интерфейс не меняются; всё ниже — устройство и упаковка.

Основания: `HTML_SIZE_AUDIT.md`, `BUILD_PIPELINE.md`, `RESOURCE_ARCHITECTURE.md`, `LOADING_PERFORMANCE.md`,
`DEPLOYMENT_OPTIONS.md`, сырые результаты — `results/`.

## 1. Что сохранить без изменений

| что | почему |
|---|---|
| **Данные карты как есть** (`data/maps/<карта>/*.json`, точные числа, `-0`, навмеш, высоты, укрытия, прострелы, видимость) | точность = поведение; любая переупаковка — только без потерь |
| **Автономную HTML-сборку** как формат | офлайн, один файл, привычна владельцу; измерено: 0,57–1,01 с старт, 200 FPS |
| **Сборку из `src/game`** (склейка по именам + esbuild для каналов) | проверена, даёт воспроизводимый артефакт; модули уже есть |
| **Проверки сборки**: синтаксис, `gen_maps --check` (файлы, замки, дубли, владение полями), обязательные файлы набора, пересчёт `nadeguess` по hash | это страховка от «нейронка создала файл/дубль»; они реально ловят ошибки |
| **Отпечаток 8 матчей** и сценарии отметок | единственная проверка «игра не изменилась» |
| **Механизм отметок** (`__SNAP`, снимок, перемотка, ключ `store` карты) | рабочий инструмент владельца; при любом переносе он должен остаться |
| **Разделение данных**: `walls` — рисование, `map3d` — симуляция, `navmesh` — ход | уже правильное; не смешивать |

## 2. Что изменить (с ожидаемым эффектом)

### 2.1. Упаковка: один движок + пакеты карт (вариант B)

- `engine.<hash>.js` (2,0 МБ), `maps/<id>.<hash>.map` (пакет данных), `sounds.<hash>.*`, `fonts.*`, `hud-photos.*`.
- Движок и звуки/шрифты грузятся один раз и кэшируются; вторая карта — только её пакет.
- **Эффект:** −4,35 МБ общих копий на каждую следующую карту; повторный запуск — только проверка манифеста.
  Первая загрузка не ускоряется (байты те же), ускоряется вторая карта и повторные загрузки.
- **Цена:** `MAP` перестаёт быть синхронным литералом; нужен `boot(map)` и перенос инициализации (`010`→`060`).
  Это изменение устройства, а не косметика: делать после того, как каналы стали модулями (фаза 3.1 генплана).
- **Проверка:** отпечаток бит в бит + сверка лучей/бросков/маршрутов (методика `bench/stage3`).

### 2.2. Бинарные форматы для тяжёлых данных

- `map3d` — бинарные zlib-блоки вместо base64 в JS-литерале; `navmesh` — плоские массивы (`Int16/Float32`) вместо JSON.
- **Эффект (измерено):** Ancient −2,45 МБ (25 % поля, 15,5 % страницы), Mirage −0,52 МБ; минус `atob` и пик
  памяти на декодирование (в профиле Ancient `atob`+`dec` ≈ 110 мс).
- **Не трогать:** сами координаты и структуру (те же числа, тот же порядок), только упаковка. `tactics`, `pro`,
  `lineups`, `nadelanes` оставить JSON: их правят руками, они < 600 КБ.
- **Проверка:** sha256 распакованных данных до/после + сверка 1200 лучей / 900 ходов / 48 бросков.

### 2.3. Отложенная загрузка ресурсов показа

- Звуки (1,71 МБ) — внешним файлом, декодирование по первому жесту (уже так и работает).
- Фото HUD (0,43 МБ) и шрифты (0,48 МБ текста) — после первого кадра, с сохранением вида (согласовать с владельцем).
- Редакторы/демо (≈0,25 МБ JS) — отдельным бандлом по кнопке.
- **Эффект:** страница для игры уменьшается на ~2,6 МБ (Ancient), старт не меняется (эти ресурсы не участвуют
  в расчёте), память страницы снижается после выгрузки/без загрузки.
- **Риск:** первый звук/фото/шрифт с задержкой; это вид, а не логика — решение владельца.

### 2.4. Единая точка входа (вариант C) — после B

Один URL, список карт, выбор; при смене карты — перезагрузка состояния (или страницы с `#map=`). Не начинать с C:
сначала B, иначе нечего выбирать.

### 2.5. TypeScript и Rust — по этапам генплана, не сразу

- **TypeScript** — после фазы 3.1 (все каналы — модули): типы состояния из `rebuild/gen/vars.json`, по каналу за шаг,
  бит в бит. Главные препятствия сняты аудитом: общая область видимости, 86 переменных с записью из чужих файлов,
  снимок по именам `var` — всё это требует явных интерфейсов, а не «накинуть типы».
- **Rust** — после TS-границ и только там, где измерен выигрыш: `m3Cast`, гранаты, навмеш. По `bench/stage3`:
  Native 1,57 мс против 2,93 мс JS на 1200 лучей, 1,17 против 2,08 мс на 48 бросков, 22,4 против 33,2 мс на
  400 маршрутов; WASM ближе к JS по скорости, но даёт память 188 МБ на данные. **Выигрыш в FPS нулевой** на этой
  машине (2D/3D уже 200 FPS) — Rust нужен для старта/массовых прогонов, а не «чтобы было быстрее в кадре».
- **Не переносить всю игру в Rust:** UI/рендер/HUD (1,0 МБ исходника) — это годы работы и потеря вида.

### 2.6. Сборка и артефакты

- Складывать артефакты в `dist/` (в `.gitignore`), а не в корень: `dist/sim.html`, `dist/<карта>-radar.html`,
  `dist/<карта>.map`, `dist/engine.js`. Сейчас `sim.html` и `mirage-radar-check.html` лежат в корне и путаются
  с исходниками (11,4 МБ диагностической копии).
- Добавить **хэш содержимого** в имя артефактов и манифест версий; подпись версии — из одного места (сейчас ветка
  и `DECISIONS.md` — два источника).
- Одна команда на всё (см. §6): сборка, запуск, проверки, граф, замеры, аудит загрузки.
- `nadeguess`-пересчёт сделать явным шагом с таймером в логе (сейчас он молча запускает 20-секундный подпроцесс).
- Оставить `sim.html` как отдельную цель (`build --test`), а не как побочный продукт: сейчас его перезаписывает
  `measure.py`, и версия в корне может не совпадать с той, что играли.

## 4. Решения, которые требуют согласования владельца

1. **Формат(ы) распространения:** оставить только автономный HTML (A) или добавить B (движок + пакеты) и позже C
   (один URL). От этого зависит всё остальное.
2. **Загрузка звуков/фото/шрифтов после первого кадра** — влияет на вид и первый звук (пусть на доли секунды).
3. **Бинарные форматы** — согласие на смену формата `map3d`/`navmesh` (данные те же, читать их станет сложнее
   глазами; для отладки можно оставить JSON-дамп).
4. **TypeScript и Rust:** порядок, границы, где именно WASM, и что считается приёмкой (отпечаток + сверка лучей).
5. **CS2 Manager:** в репозитории интеграции нет; нужен контракт (HTTP API? файлы? deep links?) — без него нельзя
   выбрать между B/C и D.
6. **Отметки:** при смене адреса/домена переезжает хранилище (`localStorage`/артефакт); нужно решение, переносить
   ли существующие базы и как.
7. **Что хранить в git:** артефакты страниц (сейчас 25 МБ в git) — оставить как у владельца или перейти на сборку
   при публикации (в `rebuild/PLAN.md` фаза 0 это уже предлагалось).

## 5. На каком этапе генерального плана (`rebuild/PLAN.md`)

| изменение | этап | почему |
|---|---|---|
| `dist/`, хэши, единые команды, чистка корня | **фаза 2** (каркас) | не меняет игру, уменьшает путаницу и контекст агентов |
| редакторы/демо отдельным бандлом | **фаза 2** («показ отдельно от симуляции») | уже есть разделение показа/симуляции |
| бинарные `map3d`/`navmesh` | **фаза 2–3**, отдельной задачей | чистая упаковка; проверяется сверкой, не прогоном поведения |
| `boot(map)` + пакеты карт (B) | **после фазы 3.1** (все каналы — модули) | нужны границы инициализации; иначе порядок загрузки поедет |
| C (единый вход) | **после B** | надстройка над пакетами |
| TypeScript по каналам | **фаза 3**, по одному каналу | канал уже модуль; типы состояния из `vars.json` |
| Rust Native / WASM | **после фазы 3**, до фазы 4 (поведение) | нужны стабильные границы ядра; иначе переносить придётся дважды |
| D/F (нативный хост, два хоста) | **после** TS/Rust-ядра | иначе два UI разойдутся |

## 6. Удобство дальнейшей разработки: структура и команды

### 6.1. Предлагаемое дерево (минимальные изменения к текущему)

```
sim-cs2/
├── src/                    ТОЛЬКО исходники
│   ├── game/               движок и интерфейс (90 файлов, 4,1 МБ) — как сейчас
│   ├── marks.js            отметки
│   └── build/              build.py, gamesrc.py, mapset.py, mkpub.py, marks_build.py, syntaxcheck.py
├── data/
│   ├── maps/<карта>/       данные карты: исходники + запечённые JSON + _build.json (как сейчас)
│   └── sounds/             MP3-исходники + sounds.json (индекс)
├── tools/                  map/ map3d/ nades/ measure/ marks/ rebuild/ audit/
├── docs/
│   ├── ARCHITECTURE.md …   действующие документы
│   └── audit/architecture/ ЭТОТ аудит: 6 отчётов + README + instruments/ + results/
├── dist/                   артефакты (в .gitignore): sim.html, <карта>-radar.html, engine.js, maps/*.map
└── tasks.ps1               единые команды (обёртка; внутри — те же python/node)
```

Правила, чтобы артефакты и большие данные не попадали в контекст AI-агентов и Graphify:
- `dist/`, `graphify-out/`, `bench/**/data/*.bin`, `.tmp/`, `__pycache__`, `*.pyc` — в `.gitignore`;
- `AGENTS.md` (или раздел в `CLAUDE.md`) со списком «что читать»: `src/game/NNN_*.js`, `data/maps/<карта>/*.json`
  (кроме `throws.json`, `demorounds.json`), `docs/ARCHITECTURE.md`; и «не читать»: `dist/*.html`, `*.bin`,
  `graphify-out/graph.json`;
- Graphify запускать по `src/`, `tools/`, `docs/` — без `dist/` и `data/maps/*/map3d.json` (иначе 6,6 МБ графа и
  шум);
- настоящие исходники (`src/game`, `data/maps`, `tools/map`) и диагностика (`tools/audit`) остаются читаемыми —
  это не «сгенерированное».

### 6.2. Единые команды (одинаково для Claude Code, Codex, DeepSeek Harness)

Одна точка входа `tasks.ps1` (PowerShell; на Linux/macOS — `tasks.sh` с теми же именами) и/или `justfile`:

| команда | что делает |
|---|---|
| `tasks build [-Map ancient,mirage]` | сборка страниц и пакетов в `dist/` |
| `tasks dev -Map ancient` | локальный сервер + пересборка по изменению (без публикации) |
| `tasks test` | синтаксис + `gen_maps --check` + `map_check.py` + короткий отпечаток (2 матча) |
| `tasks fingerprint` | полный отпечаток 8 матчей (перед/после правки) |
| `tasks graph` | `gen_maps.js` (реестр, поля, тик, переменные) |
| `tasks measure -Map …` | `sim.html` + прогон/сравнение (на ПК владельца) |
| `tasks audit:load` | измерительная копия + `load_probe.py` + `summarize.py` (этот аудит) |
| `tasks audit:size` | `html_inventory.js` по обеим картам |

Требования к командам: без абсолютных путей, без `cd` в скриптах, `NODE_PATH` для acorn/esbuild выставляется
внутри; на Windows npm звать через `npm.cmd` (политика PowerShell блокирует `npm.ps1`); вывод короткий; артефакты —
только в `dist/`.

## 8. Риски и защита

- **Порядок инициализации** — главный риск при `boot(map)`: `applyWalls` (030), `rebuildNav` (050), `computeZoneDanger`
  (060) вызываются на верхнем уровне. Защита: отпечаток бит в бит и сверка лучей/маршрутов после каждого шага.
- **Снимок отметок** привязан к именам `var`: при TS-переносе снимок должен получить явный реестр состояния,
  иначе перемотка сломается. Защита: сценарии отметок (`tools/marks/scenarios.js`) до и после.
- **Вид** (шрифты/фото/звук при отложенной загрузке) — только с согласия владельца и скриншотами до/после.
- **Точность** — не менять числа; любые «оптимизации» геометрии запрещены (прямое требование задания).
- **Не начинать миграцию** до утверждения окончательной архитектуры; этот документ — предложение, а не решение.
