## 22.10.2026 — Пути по стенам и гуськом (v405, снимки владельца со слоя «пути игроков», Mirage, спавн T) — без прогона
- Владелец: «зачем они все идут по одному пути»; «там забор так не перепрыгнуть» (путь T0 через верх стены на −42); «застревают и путь
  куда-то уходит» (T на низкой стенке над T Ramp).
- Застревание — от v403 (`offNavStep`: вне пола — не дальше от пола): бот на краю стенки не спрыгивал по пути. Теперь шаг вдоль пути
  к следующей точке (`navStepAlongPath`) — можно.
- Граф пути (`rebuildNav`, с 3D-геометрией): выкинуты участки .nav, под которыми в геометрии нет пола на их высоте (`NAV_FLOOR_TOL` 24),
  и «гребни» — тонкие (< `NAV_RIDGE_W` 6) участки, у которых по обе стороны пол ниже больше чем на ступеньку (верх стен / перил).
  Mirage — 47 из 2544, Ancient — 82 из 1970. Подъёмы из демок (`climbs`) без пола наверху — не строятся (Mirage 105 из 123).
- Разные пути: у бота своя полоса — точки поворота пути сдвигаются поперёк движения на (lane − 0,5)·2·`LANE_W` (14), если остаются
  на полу (`laneShift`); выбор маршрута — цена перехода × (1 ± `ROUTE_NOISE` 0,25) по клетке 40 (`zoneDijkstra.noise`). Числа —
  **проектные**. Не помогло на спуске со спавна T: там T идут гуськом по бордюру (короче рампы); про по рампе — 71 %. Следующий шаг.
- Проверка: пути T на спавне матча 1 (T больше не встают на стенке, путь не идёт по верху стены), по 2 раунда на картах без ошибок;
  раунд 2 Mirage (матч 3) — без планта и в v404. Прогон ПК не делался.

## 22.10.2026 — Слой «пути игроков» (v404, владелец)
- Владелец: «видеть пути игроков по кнопке». «Слои» → «пути игроков» (`chkPaths`, рисование — `620_draw`): у каждого живого игрока
  линия пути по навмешу от него до точки задачи (`b.path` с `pathIdx`), кольцо — точка задачи с номером игрока и задачей, треугольник —
  смена этажа на пути (разница высоты точек > `JUMP_UP`, вершиной вверх / вниз), бледный пунктир — пройденное за ~2 с (`b._trail`).
- Только рисунок — игру не меняет.

## 22.10.2026 — Высота бота и цель пути (v403, три отметки владельца с Mirage); прогон отменён владельцем — влито без замера
- Отметки (матч 1, раунд 1) разобраны по истории (`tools/mark_story.js`, бит в бит): A Default — CT4 «прошёл сквозь укрытия»;
  Window — CT0 «застрял в стене»; спуск T Ramp — T «идут по бордюру и падают».
- Высота бота — одно место `navFollowFloor` (370): после шага пути и в конце цикла бота после любого движения (бой
  `fightCycleTick`, у угла, пик). Раньше — только после шага пути: в бою бот сходил с ящика и шёл на его высоте. В щели — пол на
  своей высоте или ниже (`navNearestFall`), выше — только если ниже нет; своего пола нет — вниз падает всегда, вверх — по связи.
- `navOnFloor`: щель к участку только с обратной связью («спрыгнуть оттуда») — не шаг туда выше ступеньки (с пола в ящик 70).
  `offNavStep`: уже вне пола — не дальше от пола своего уровня (`navFloorDist`, `NAV_OFF_R` 24 — **проектное число**).
- `buildWaypointPath`: цель вне навмеша — ближайшая точка участка цели (`navClampInto`), высота цели не задана — его пол (раньше
  0 = «не знаю»: лестница вставляла подъём на −46 за стеной у Window).
- Бордюр у T Ramp — не правился: по 30 демкам про идут по нему в 29 % проходов, боты (v398) — 36 %.
- Проверка: повтор отметок (CT4 больше не на высоте ящика и не в ящике; CT0 идёт к Window по коридору), раунд на каждой карте без
  ошибок. Прогон ПК (база v402 / правка, 8 матчей) отменён по решению владельца — цифры сторожа не мерены.
