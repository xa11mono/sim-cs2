# Задание DeepSeek Harness: подключить отметки владельца sim-cs2

Нужно восстановить в DeepSeek Harness тот рабочий процесс, который раньше выполнялся в Claude: владелец ставит отметку в матче, а агент сам находит эту отметку, читает её текст и снимки, воспроизводит эпизод, проверяет гипотезу/исправление и сообщает результат.

## Сначала только диагностика — код пока не менять

Работай в открытом репозитории `sim-cs2`. Сначала прочитай корневой `CLAUDE.md`, `rebuild/RULES.md` и только относящиеся к отметкам части `src/marks.js`, `tools/marks/README` (если есть), `tools/marks/mark_open.js`, `mark_story.js`, `mark_frames.js`, `mark_video.js`, `scenarios.js`, а также `rebuild/scenarios.json`.

Проверь фактическую конфигурацию текущего DSH-сеанса: доступны ли локальная файловая система, bash/PowerShell, Playwright/Chromium, browser-use/CDP и возможность работать с уже авторизованной страницей Claude Artifact. Не предполагай, что любой из этих инструментов установлен.

## Установленные факты в проекте

- Запись отметки содержит `match`, `round`, `roundTime`, `tick`, `category`, `priority`, `text`, `want`, `bot`, `status`, `version`, `fp`, `state`, `snapAsset`, `preSnapAsset`, `preTick`, `frameAsset`, `screenAsset` и временные поля.
- В `src/marks.js` DB и Assets подключаются только при наличии `window.claude` и `claude.use("db")` / `claude.use("assets")`.
- Коллекция отметок называется `marks`; снимки хранятся как asset IDs. В интерфейсе ссылка на asset читается через `/_blob/<asset-id>`.
- Если Claude host API недоступен, в коде отметки попадают в `MK.local` и предупреждается, что они живут только до перезагрузки. Кнопка «Скопировать все» копирует текст, но не снимки.
- `mark_open.js` открывает момент отметки. `mark_story.js` берёт pre-snapshot примерно за 15 секунд до неё, повторно считает до тика отметки и сверяет состояние с snap. `mark_frames.js` и `mark_video.js` строят визуальные доказательства. `scenarios.js` прогоняет регрессионные сценарии из `rebuild/scenarios.json`.
- Важнейшее правило: снимок момента уже несёт старое принятое решение. Чтобы проверить, как решение принимается новым кодом, нужен `preSnap` и повтор до `tick`, а не только `snap`.

## Цель интеграции

Сделать так, чтобы DSH мог без ручного указания ID находить и читать реальные отметки и их снимки, а затем использовать существующие инструменты проекта. Не переписывай систему отметок заново и не ломай совместимость страницы с Claude.

Проверь два возможных пути в таком порядке:

1. **Прямой доступ через авторизованный browser session**, только если текущий DSH действительно может открыть исходный Artifact в авторизованном Chrome/Chromium и прочитать из контекста Artifact реальные документы коллекции `marks` и их assets. Проверь это на одной существующей записи. Не используй внутренние/недокументированные приватные API и не обходи авторизацию.
2. Если прямого доступа нет, предложи минимальный поддерживаемый экспорт из страницы владельца: метаданные записи плюс бинарные `snapAsset` и `preSnapAsset` (а также frame/screen при наличии). Предпочти один понятный экспорт всех новых/выбранных отметок в zip/папку. Не называй это полностью автоматической синхронизацией, если владельцу всё ещё нужно нажимать кнопку или переносить файл.

Если из текущего DSH-сеанса невозможно прочитать Artifact DB/assets и нельзя безопасно подключиться к авторизованной странице, остановись на диагностике и сообщи конкретный недостающий доступ. Не подменяй реальные данные синтетическими и не делай вид, что отметка прочитана.

## Единый локальный формат для DSH

После согласования реализации используй:

```text
tools/marks/inbox/
  index.json
  <mark-id>/
    record.json
    snap.json
    pre.json
    frame.jpg       # optional
    screen.jpg      # optional
```

Сохраняй исходный ID и все исходные поля mark record. Snapshot JSON выгружай без потери полей. Для старых отметок без `preSnapAsset` сохраняй `pre.json` отсутствующим, не создавай искусственный снимок.

## Skill для постоянного поведения

В репозитории должен появиться skill:

` .agents/skills/sim-cs2-marks/SKILL.md `

В этой папке уже будет подготовлен файл `SKILL.md` из этого пакета. Перенеси его в репозиторий без изменения смысловых правил. Убедись, что текущий DSH-профиль включает `@deepseek-ai/dsh-skill`, `@deepseek-ai/dsh-skill-filesystem` и `@deepseek-ai/dsh-tool-skill`, либо использует другой подтверждённый механизм skills. Проверь, что skill отображается в каталоге и вызывается через `/sim-cs2-marks`.

Сам skill отвечает за постоянный процесс работы с данными. Он не заменяет доступ к Artifact DB/assets — этот доступ нужно доказать отдельно.

## Приёмка — без неё не считать задачу выполненной

1. DSH находит хотя бы одну реальную сохранённую отметку без того, чтобы владелец называл её ID.
2. DSH получает и показывает её реальные метаданные, `snap.json` и, если существует, `pre.json`.
3. `mark_open.js` успешно открывает её снимок.
4. Если есть pre-snapshot, `mark_story.js` доходит до `tick` и печатает результат сверки. При несовпадении DSH явно помечает историю как невоспроизведённую.
5. DSH может создать/запустить один тестовый сценарий через `scenarios.js` и различает ответы «да», «нет», «ситуация не возникла», «ошибка/снимок не сошёлся».
6. Следующий запрос владельца о похожей игровой проблеме автоматически запускает поиск релевантных `new` / `unparsed` / `fixed` отметок и предлагает конкретный ID/эпизод к разбору.
7. Claude Artifact storage и текущая страница продолжают работать без регрессии.

## Ограничения

- Не менять `main`, не публиковать страницу, не сливать ветки и не запускать ПК-прогоны без согласования.
- Следовать `CLAUDE.md`: сначала диагноз и эпизоды, затем согласование, затем изменение кода; наборы A и B; доказательство только по фактическому воспроизведению.
- Не создавать новые файлы в `src/game` и не добавлять обходные замки/дубли решений.
- Не менять status отметок автоматически.
- Не читать целиком большие сборки/карты/демки и не печатать большие JSON в чат.
