# План по разбору отметок Mirage 04.11 (v512) — по устройству, а не по ситуациям

Разбор причин — `docs/reports/MARKS_MIRAGE_2026-11-04.md`. Ответы владельца на вопросы — сообщения 04.11 (перенести в PRINCIPLES.md).
Правило: каждая группа чинит **одно устройство** так, чтобы ситуация не повторялась нигде; старые заплатки этой механики удаляются
в той же правке. Проверка группы: раунды отметок группы из снимков → один прогон 8 матчей × 2 карты против v512.

## Г1. Правда движка и данных (то, что потом читают все решения)
Если тут ложь — любая логика выше ошибается, и её «чинят» заплатками.
- высота бота = пол под ногами (`navFloorZ`), не одна высота участка (п.15б);
- «чекнул — пусто» только про то, что реально видели (сейчас 2/3 точек зоны — враг в невидимой трети «исчезает»);
- пуля сквозь дым — обычная пуля (урон тому, кто на линии) (п.5);
- сейв CT: у дефузящего — оставшееся время дефуза; ретейк «успеем ли» — по пути, не по прямой (п.4, п.3);
- Side Alley: уступ 50 ед. в навмеше и 3D — ждёт скриншот владельца с Mirage.

## Г2. Знание о врагах → взгляд и решения (одна модель вместо весов-заплаток)
- угроза: последнее место врага расходится по путям со скоростью бега (`reach*`), без пола 0,5 и без 0,3 для незасвеченных;
  проверенное пусто = 0, пока туда не успел бы дойти известный враг (ответ 2);
- взгляд на звук/инфу: место видно — смотреть на место; на пути к врагу свой — не туда (п.18, п.28);
- контакт мидера — условная помощь, если мид не остаётся без контроля (ответ 8, заменяет v408);
- отход от известного врага — держит направление его появления (ответ 2).

## Г3. Арбитр задач: одно решение — одно место, без «туда-обратно»
- дефузер — не пересчитывается от точки, которую задаёт сама роль (п.32);
- проба — срок от прихода на точку (п.16);
- «ждать гранаты» — только `exuGate` (убрать второе в `utilWait`) (п.30);
- смена места дефолта — по событию, таймер `DEF_STAND` убрать (п.27/29, ответ «по геймсенсу»);
- задания гранат не затирают друг друга; граната своего боя не съедает гранату плана (п.19, п.9);
- «мало HP» и «рядом погиб свой» — разные задачи; второе — сменить позицию, держа фланг (п.1, ответ 1);
- сейв T/CT — по шансу раунда и знанию, не жребием и не «пока расклад тот же» (п.10, ответ 6А);
- колл/ротация CT пересматриваются, когда враг ушёл с направления (п.11, ответ 6Б).

## Г4. Позиции и движение в бою
- дефолт T играется с начала раунда: никто не стоит на спавне; точка дефолта — внутри своей зоны (п.12, п.13).
  Сначала проверить данные `defaultpos.json` (T Spawn 0,27 — подозрение владельца: эко-паузы в демках);
- ретейк: первый + второй на размен, остальные на других входах за укрытием (п.3, п.31, ответ 3);
- за укрытием — держит / джигл / меняет место (п.6/24, ответ 4);
- смок на самом посте и закрытый угол — одно правило (п.21, ответ 7Б);
- точка обхода — проверки по настоящему пути с высотой (п.26); не выходить на врага на перезарядке (п.2б).

## Г5. Гранаты: кто, когда и каким броском
- хозяин гранаты — по ответу 5 (есть граната и бросок, маршрут не ломается, успевает), а не по деньгам в закупе (п.7, п.9);
- мидер ждёт смок, перекрывающий линию на его пути (п.8); под флешку выходит тот, кто стоит выгоднее (п.14, ответ 7А);
- подбор броска: молотов не на границе 2 с, без дуг в потолок у носа (п.20, п.25); известный лайнап — надёжнее импровизации
  (умение — профиль `util` и разброс про) (п.22, ответ 10);
- статистика гранат: прямые / отскок по расчёту / случайный удар (п.23).

## Г6. Скорость (игра бит в бит та же — отпечаток, без прогонов)
- расчёт путей для взгляда и оценок — 49 % времени (кэш, реже, без пути там, где хватает прямой видимости);
- `nadeThrowSpot` — фризы до 0,5 с.

Порядок: Г6 (дёшево, ничего не меняет) → Г1 → Г2 → Г3 → Г4 → Г5. Каждая группа — своя версия и свой прогон.
