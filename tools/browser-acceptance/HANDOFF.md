# Р5.10 · Приёмка браузерных сборок

Основа — `v636a` (`7aba8b8`). Сценарии Playwright открывают штатный интерфейс Ancient и Mirage. Тесты идут в отдельном контексте браузера с пустым хранилищем и через обычные элементы управления. `window.__ev` используется для подготовки воспроизводимого состояния матча и проверок результата. В сценарии полного снимка отметки тест подставляет локальный транспорт базы и файлов в изолированной вкладке.

## Что проверяется

| Сценарий | Проверка |
|---|---|
| Интерфейс | Страница нужной карты, запуск тиков, пауза без продвижения времени, запуск матча по номеру |
| HUD | Счёт, названия команд, по пять карточек каждой стороны, выбор игрока |
| 2D | Радар рисует непустой кадр. Сохраняется PNG |
| 3D | WebGL2, готовый кадр, кнопка зума, возврат к радару. При отсутствии WebGL2 тест проверяет работающий радар и причину в UI |
| Звук | Щелчок пользователя, состояние AudioContext, отключение/включение, изменение gain и запись громкости |
| Отметки | Валидация пустого текста, сохранение и список в автономном HTML, полный снимок и возврат к сохранённому тику через имитацию транспорта артефакта |
| Редакторы | Вкладки стен, высот, укрытий и прострелов, панель лайнапов, выбор режима зон и выравнивания навмеша |
| Песочница | Список десяти ботов, отключение и включение ИИ, выход |
| Повторы | Штатная регрессия `replay_rewind.js`, открытие зарегистрированного клипа из меню, пропуск через UI |

## Запуск

Node 24+, Python 3 и Playwright 1.62.1. Playwright должен разрешаться из Node как обычная зависимость. При самостоятельной установке можно держать его отдельно от репозитория и указать каталог `node_modules` через `NODE_PATH`.

```sh
mkdir -p dist
python3 src/build.py --map ancient dist/ancient.html
python3 src/build.py --map mirage dist/mirage.html
node tools/browser-acceptance/check.mjs tools/browser-acceptance/builds.example.json dist/browser-report
```

`SIM_BROWSERS` принимает список `chromium,firefox,webkit`. `CHROMIUM_PATH` позволяет запустить установленный Chromium. Третий аргумент команды проверяет PNG по предыдущему `report.json` для той же пары «движок / версия», карты и ID сборки. Базы нужно записывать на одной платформе, с одним набором шрифтов и одним режимом GPU. PNG и подробный JSON пишутся в каталог отчёта. Ошибка запуска, исключение страницы, падение проверки и несовпадение скриншота дают код 1. Штатный 2D или локальный список отметок учитываются как `fallback`.

## Подключение сборок Р5.6

В JSON добавить по записи для каждой карты каждой сборки. `entry` принимает путь относительно манифеста либо URL локального стенда. Для автономного HTML на всех картах каждой карте соответствует одна запись с общим `entry`. Для варианта B укажите входную страницу сервера с пакетами. `adapter` задаёт относительный путь к JS-модулю, экспортирующему `scenarios`. Он может выбрать карту в общем HTML и подготовить тестовый кадр через будущий API Worker, затем переиспользовать UI-сценарии из `legacy.mjs`. Драйвер сверяет наличие сценариев. `assetOrigins` добавляет нужные адреса ресурсов стенда, а все прочие сетевые обращения перехватываются.

## Ручная приёмка

| Где | Что сверить на каждой карте |
|---|---|
| Chrome, Brave, Opera GX, Edge, Firefox, Safari | Загрузить каждую сборку с чистым профилем. Открыть матч, сверить HUD и движение на радаре, перейти в 3D, изменить камеру, вернуться в 2D. |
| Те же браузеры со звуковым выходом | Щёлкнуть по игре, услышать сигнал при включении звука, проверить громкость, шаги и выстрелы. |
| Страница с реальным хранилищем | Создать и открыть отметку со снимком. В редакторах сохранить небольшую правку, перезагрузить, проверить правку и отменить её. |
| Р5.6 и следующие сборки | Для Worker/WASM проверить, что выбран ожидаемый режим, а при целевом недоступном API работает штатный резерв. Для повторов сверить живой клип, переход обратно в матч и пропуск. |

Поддержка программного WebGL2 и аудиовыхода зависит от среды. Полный список продуктов и будущие сборки принимаются отдельно.

## Результат облачной проверки

Проверены обе карты на Chromium 151.0.7922.34, Firefox 153.0 и WebKit 26.5. В Chromium и WebKit прошли также WebGL2 и включение звукового контекста. В Firefox окружение вернуло отказ WebGL2 и игра осталась на рабочем 2D. После пользовательского клика аудиоконтекст Firefox остался в состоянии `suspended`, поэтому тест звука выдал ошибку. Остальные сценарии Firefox прошли на обеих картах. Отчёт хранится в `evidence.json`. В повторе Ancient на Chromium три кадра (HUD, 2D и 3D) совпали побайтно.
