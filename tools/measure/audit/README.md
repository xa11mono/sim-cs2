# Аудит поведения ботов (11.10.2026)

Отчёт: `docs/reports/BOT_BEHAVIOR_AUDIT_REPORT.md` (+ `.docx`).

| файл | что делает |
|---|---|
| `run_audit.py <метка> --sim=<сборка.html> --matches=3,7,…` | делает из сборки копию с записывающими крючками (только запись: `__AUD.leak`, `__AUD.call`, метка источника у гипотезы «слышали»), играет матчи по 2 параллельно, пишет `runs/<метка>/aud_<матч>.json` |
| `audit_rec.js` | запись одного матча: утечки знаний в общую точку команды, взгляд на спрятанного врага (с плацебо «3 с назад / через 3 с»), повороты без новой информации, первое появление врага → прицел → первый выстрел, смены поста (кто сменил) и дребезг, смены сайта T (маршруты, гранаты), коллы CT, броски гранат, ослепления, урон по своим, войс, смерти |
| `analyze.py <метка> [<метка2>]` | показатели по механикам; две метки — «до / после» на тех же матчах; пишет `runs/<метка>/summary.json` |
| `scenarios.js` | 7 коротких сценариев-регрессий (реакция на первый контакт, обзор в перестрелке, утечка «ухо → команда», дребезг «сейв ↔ лайнап», выбор места опорника, смена сайта T, граната под своего). `node src/q.js <сборка.html> "$(cat tools/measure/audit/scenarios.js)"` |

Крючки проверены: сборка аудита играет бит в бит как обычная (те же фраги на тех же тиках в матчах 3, 7, 11).
Стандартные метрики против про — `tools/measure/measure.py` (метки прогонов `audit_before`, `audit_after2`).
