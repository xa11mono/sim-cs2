# Система сборки: от исходников до готовой игры (v598, 24.11.2026)

Аудит только читает код. Проверка воспроизводимости: `python3 src/mkpub.py --map mirage` во временную копию дала
9 438 322 Б против опубликованных 9 434 168 Б — разница 4 154 Б, это подпись версии и дата (`simVersion`), т.е.
**опубликованные страницы собираются из текущих исходников**.

## 3. Полная цепочка

```
data/maps/<карта>/ (исходники: .nav, .txt, radar, демки, рецепт _build.json)
        │  python3 tools/map/map_build.py <карта>   (шаги: navmesh, walls, heights, cover, zones, zones3d,
        │                                            wallbang, map, demos, spawns, checklooks; часть файлов «заморожена»)
        ▼
data/maps/<карта>/*.json + radar.png  ──► src/mapset.py: map_js()   (проверка обязательных файлов, nadeguess по hash)
        │
src/game/*.html|js ──► src/gamesrc.py:game_source()  (склейка по порядку имён; модули — меткой /*@@MODINIT X@@*/)
        │                        │
        │                        ├─ src/marks_build.py:inject()  → __SNAP (все var верхнего уровня) + marks.js
        │                        ▼
        ├──────────────► src/build.py  → sim.html  ──► esbuild (каналы-модули) ──► syntaxcheck ──► gen_maps --check
        │
        └──────────────► src/mkpub.py  → <карта>-radar.html:
                              inject_map(inject(game_source()))
                              + SND_DATA из data/sounds/sounds.json
                              + подпись версии (ветка/ DECISIONS)
                              + вырезание строк-комментариев «//»
                              + esbuild --compact (минификация пробелов)
                              + syntaxcheck
```

Порядок подключения кода определяется **именем файла** (строковая сортировка `000…990`), а не списком в конфиге.
21 файл из `rebuild/modules.json` не склеивается, а бандлится esbuild: в склейке на его месте стоит метка
`/*@@MODINIT <файл>@@*/`, ядро вызывает `__mi_<файл>` в этой точке — порядок выполнения при загрузке сохраняется
(`tools/rebuild/mod_build.js`). esbuild собирает всё в одно пространство имён (scope hoisting), а `import/export`
генерирует сам по разбору acorn: модуль берёт у ядра имена, объявленные в ядре, ядро берёт у модуля объявленные в нём.

## 4. Явные зависимости

- `python3` (3.10), `node` (24.x), `npm` (ставит `tools/rebuild/package.json`: esbuild 0.24.0, acorn 8.14.0, acorn-walk 8.3.4).
- Обязательные файлы набора: список `MAP_FILES` в `src/mapset.py` (23 файла) — нет файла, сборка падает с текстом.
- `data/sounds/sounds.json` — для публикуемой страницы (в `sim.html` не вставляется).
- `tools/rebuild/gen_maps.js --check` — проверка устройства (падает сборка): новый файл без `rebuild/files.json`;
  новый замок `_xxxUntil` без `owners.json`; две функции с одним именем; общая переменная, которую пишет чужой файл,
  без категории/хозяина (`rebuild/var_cats.json`); поле перенесённого канала пишут мимо хозяина (`owners.json`).
- `src/syntaxcheck.py` — `new Function()` по каждому `<script>`; битая страница не доходит до замеров.

## 5. Скрытые зависимости (не видны из `build.py`)

1. **`nadeguess.json` проверяется по отпечатку кода и данных** (`mapset.py:nade_hash`): если код гранат (файлы `035_`,
   `080_`, `360_`, `365_`, `380_`, `385_`, `390_`, `400_`) или данные карты изменились — сборка сама запускает
   `tools/nades/guess_bake.py` (≈20 с) и падает, если подбор не пересчитался. Это скрытый тяжёлый шаг сборочной
   машины и скрытая зависимость от `nade_hash`.
2. **Подпись версии** берётся из имени текущей ветки (`vNNN`), иначе из последней записи `docs/DECISIONS.md`
   (`mkpub.py:_branch_ver`). Значит, одинаковый исходник в разных ветках даёт разные байты страницы.
3. **`data/sounds/sounds.json`** — данные, которых нет в `src/`; без файла страница соберётся молча без звуков.
4. **Реестры `rebuild/*.json`** участвуют в падениях сборки, но не в её результате; их правка меняет только проверки.
5. **Порядок загрузки**: `var` в начале файла может читать `var` из файла с меньшим номером; перенос строки/файла
   меняет поведение. `applyWalls()` (030) вызывает `rebuildNav()`, `computeZoneDanger()` (060) вызывает `m3()` —
   это загрузочные вызовы верхнего уровня, а не «инициализация после загрузки».
6. **`window.__ev`** есть только в `sim.html`; его вырезает `mkpub.py`. Инструменты, которые «выполняют код в игре»,
   работают только с `sim.html`.
7. **Снимок отметок** (`marks_build.py:top_vars`) перечисляет `var` регуляркой по тексту; переменные каналов-модулей
   берутся из `module_source()`, их запись переписывается сборщиком на сеттеры `__set_*`. Новый `var` в игре
   автоматически попадает в снимок — это удобно, но привязывает снимок к именам переменных.
8. **Windows-особенности**: `build.py` ищет `node`/`npm` в PATH; npm-скрипты PowerShell на этой машине запрещены
   политикой (`npm.ps1`), поэтому `bundle_modules` зовёт `npm` через `shutil.which('npm')`/`npm.cmd`; в CI шаги идут
   через `cmd`, а не PowerShell (`.github/workflows/measure.yml`).
9. **Прогоны на ПК** — отдельная цепочка: `tools/measure/request.json` в ветке `measure/<имя>` → GitHub Actions
   self-hosted → `tools/measure/remote_run.py` → результаты в `pc-results/<N>`; сборка внутри `measure.py` сама
   вызывает `src/build.py` и перезаписывает `sim.html`.

## 7. Что специфично для карты

- всё содержимое `data/maps/<карта>/` (23 обязательных файла + `demorounds`, `throws` и отчёты `_*.json`);
- `map.json`: `id`, `name`, `store` (ключ хранилища браузера), `db` (коллекция правок), `pxUnits`, `zoneLayer`,
  `spawns`, `spawnFix`, `siteAFix`, `ui` — надписи и подсказки;
- `radar.png` (в `MAP.radar` как data URI) и `radar`/`de_*_radar.png` как исходник;
- `_build.json` — рецепт: какие шаги пересобирать, какие файлы «заморожены» (у Ancient заморожены `map.json`,
  `radar.png`, `navmesh.json`, `walls.json`, `zones.json`, `pro.json`, `tactics.json`, `lineups.json`);
- список `frozen` — фактически признание, что часть данных карты нельзя воспроизвести из имеющихся исходников
  (у Ancient нет `.nav`, зоны и стены нарисованы руками).

## 8. Чем сборка мешает TypeScript и Rust

Установлено по коду, а не на глаз:

1. **Одна область видимости.** Вся игра — `(function(){ … })()`; 1001 переменная верхнего уровня, 1306 функций.
   По `rebuild/gen/vars.json` **86 переменных пишутся из чужих файлов** (например, `state`, `post`, `facing`, `path`).
   Для TS это значит: сначала интерфейсы состояния (каналы), потом типы; механически «обернуть в модули» нельзя —
   потеряется порядок инициализации.
2. **Порядок — это имя файла.** Нет ни одного импорта между 69 склеенными файлами; зависимости видны только по
   вызовам. Для TS это скрытые циклические зависимости; для Rust — отсутствие границ, по которым резать модули.
3. **Данные вшиваются как JS-литерал** (`var MAP = {…}`), а не загружаются. Для TS это `any` на входе; для Rust —
   нужен отдельный формат и загрузчик (этап 3 уже сделал прототип `bundle.bin`, но игра его не использует).
4. **Снимок отметок** перечисляет `var` регуляркой; при переходе на `let/const`/модули механизм ломается, нужен
   явный реестр состояния.
5. **Сборка не проверяет типы** и почти не проверяет данные: только синтаксис, обязательные файлы карты, реестры
   устройства. Тестов нет; единственная проверка «игра не изменилась» — отпечаток 8 матчей
   (`tools/measure/fingerprint.sh`) и сценарии отметок.
6. **`BAL`-переключатели и монолиты** (`stepTick`, `draw`, `tBrain`, `ctBrain`) — точки, где TS/Rust-граница
   потребует ручного разбиения; это работа фазы 3 генплана (каналы), а не «обёртка».
7. **UI и симуляция в одном файле и в одном пространстве имён**: 183 КБ редакторов/инструментов, HUD 1,0 МБ
   исходника, `draw` читает состояние напрямую. Для нативного клиента (Rust) нужен отдельный слой представления.

## 9. Насколько сложно добавить новую карту

Сейчас добавление карты — это **данные + две команды**, без копирования движка в исходниках:

1. положить исходники в `data/maps/<карта>/` (`.nav`, `.txt` с `pos_x/pos_y/scale`, радар, демки);
2. описать `_build.json` (рецепт, сайты, коллауты, зоны);
3. `python3 tools/map/map_build.py <карта>` — шаги из рецепта (у Ancient часть файлов заморожена);
4. `python3 tools/map/map_check.py` — не должно быть «✗» (`tools/map/map_manifest.json`: 47 пунктов, из них
   3 — «нет скрипта»: сейв, ретейк, клатч);
5. `python3 src/mkpub.py --map <карта>` — страница.

Ограничения, которые всплывут:
- **данные**: для сейва, ретейка и клатча скриптов запекания нет ни у одной карты;
- **код**: два сайта `A`/`B`, роли зон, пространство 2048×2048, радиусы в пикселях подобраны на Ancient, веса сетапов
  CT по id Ancient, палитра страницы — от Ancient (`docs/ARCHITECTURE.md`, «Что код всё ещё считает общим»);
- **размер**: каждая новая страница = 4,35 МБ общей части + данные карты; при 7 картах это 30 МБ общих копий;
- **проверки**: новая карта не проверяется автотестами, только глазами (`map_shot.js`) и прогоном.

Оценка сложности в шагах: 4 обязательных команды + 47 пунктов памятки данных + правки допущений кода (2 сайта,
масштаб, палитра) — это несколько сессий, но **без копирования движка**. Главная стоимость — данные из демок
(навмеш, высоты, укрытия, прострелы, про-места, тактики), а не сборка.

## 10. Выводы

1. Источник один (`src/game` + `src/marks.js` + `data/maps/<карта>`), артефактов много; сборка воспроизводима.
2. Порядок кода задаётся именами файлов, а не зависимостями; 21 модуль уже собран esbuild, остальное — склейка.
3. Скрытых зависимостей много: hash подбора бросков, ветка/`DECISIONS` для подписи, звуки, реестры, node/npm,
   Windows-оболочка. Всё это надо явно назвать при перестройке, иначе «сборка в другом месте» даст другую страницу.
4. Движок дублируется в артефактах (4,35 МБ на карту), но не в исходниках — это чинится форматом распространения,
   а не переписыванием кода.
5. Для TS/Rust главные препятствия — не размер и не сборка, а **общая область видимости, порядок инициализации,
   снимок по именам `var` и отсутствие границ каналов**. Их снимает фаза 3 генплана (каналы), после неё TypeScript
   становится механическим шагом, а Rust — выносом тяжёлых функций с проверкой «каждый луч/бросок совпал».
