### AUDIT-001 · Сейв T — жребий по таблице частот про
- **Категория:** СЛ, КТ · **Приоритет:** критический · **Доказательство:** A (структура); симптом владельца «сейв при любой ситуации» (E0)
- **Модуль:** `180_save_retake.js` `T_SAVE_PRO`, `tSaveRoll`, `tSaveWant`; вызов `170_tbrain.js` (блок сейва)
- **Строки:** 180:38–52 (таблица, жребий), 180:55–66 (`tSaveWant`), 170:~272–281 (включение сейва)
- **Наблюдаемая структура:** `tSaveRoll` берёт долю раундов «про в меньшинстве выжили без планта» по `[живых T][живых CT]` и корзине
  времени (>55 / 30–55 / <30 с) и бросает `hashRand(...) < P`. `tSaveWant` дополнительно требует: есть неизвестные CT, денег не хватит
  на фулл, оружие ≥ 1500, носитель не на сайте, `saveWorth`. Решение «сохранять или играть» — монетка.
- **Нарушенное правило:** «событие обновляет картину мира», «никаких „как у про“ внутри мозга» (CLAUDE.md §1); статистика стала правилом.
- **Отсутствующий контекст:** где бомба и сколько до сайта по пути; что известно о позициях CT; контроль карты; шанс изолировать
  CT по одному; кто с каким оружием; утилита на руках.
- **Цепочка влияния:** сейв снимает размены (`saveCancelTrades`), меняет посты всех T (`tSaveHold`), выключает «доигрывание».
- **Сценарий:** 2v3, бомба у T рядом с пустым сайтом, CT позиции неизвестны → в части раундов сейв по жребию без оценки.
- **Правильное поведение:** командное решение из оценки вариантов (поставить / изолировать / сейв) по знанию команды, пути, времени, экономике.
- **Что проверить:** записи `rounds` + войс «сейвлю» с раскладом и позицией бомбы; доля сейвов с носителем ≤ N с пути до пустого сайта.
- **Регрессии:** 1v4 за 15 с без бомбы рядом — сейв остаётся; пистолеты — не сейвят.

### AUDIT-002 · Сейв CT — пороги по числу живых и подгонка под среднюю цифру
- **Категория:** ЖУ, КТ, СЛ · **Приоритет:** высокий · **Доказательство:** A
- **Модуль:** `340_ctbrain.js` блок «сейв» · **Строки:** 340:~355–386 (`hopeless`), `080_bal.js:35` (`saveGap: 3`)
- **Наблюдаемая структура:** `hopeless` = `1 против saveGap+`, `cts ≤ T − saveGap`, `cts ≤ T − 2` при 2+, `1v3`, `1v2 без кита` и т. п.;
  комментарий v158: «у про после взрыва живы 2,1 CT, у ботов 1,2: сейвят раньше». Время до дефуза — по пути (`defuseEta`) — хорошо.
- **Нарушенное правило:** решение по совокупности, а не по порогу; числа из средней, не из ситуации.

  ближайшего, кроссфайр T.
- **Цепочка влияния:** сейв снимает ретейк (`updateRetake` не зовётся), отменяет размены.
- **Сценарий:** владелец Ж1 — CT дошли до точек сбора до планта, после планта по порогу — сейв.
- **Правильное поведение:** ретейк / задержка / сейв — одно командное решение по оценке шансов из знания.
- **Регрессии:** не успеть дойти и дефузнуть — сейв остаётся; все T мертвы — дефуз (v530).

### AUDIT-003 · Разрыв «ротация до планта ↔ сейв после планта»
