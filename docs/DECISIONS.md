## 22.10.2026 — Г1 (v396–v396д, М143): гранаты от тактики — план гранат по выходу из демок; в main НЕ слито (ветка `g1-nades`)
- Эталон «гранаты по выходам» из демок — `tools/route_nades.py` (ветка игрока — первая зона стороны A / B / мида набора карты;
  граната — тип + зона разрыва); планы для игры — `tactics.json` → `nadePlans` (сочетания гранат раундов про по выходу, CT по
  времени, ответ CT на выход) и `tTactics[].exit`. В игре гранаты раунда — одно сочетание по выходу тактики, все гранаты которого
  летят, если граната есть и кидающий рядом (`390`: `planNades` / `planTick` / `luGive`); ответ CT — по знанию команды
  (`beliefCount` ≥ 1, **проектное число**); тушение молотова смоком — `nadeReact`. Удалены розыгрыш лайнапа на раунд (`prob`,
  `"pr"`), `tCrossSmoke`, окна триггеров лайнапов про, `BAL.proLineups` / `nadeMore`, «молотов на раш», `tSmokeReserveOk`
  (→ запас под план `planReserved`). Итерации: план перебивает общее задание; контакт дальше 300 px (**проектное число**) не
  снимает бросок плана; граната выхода — со своей секунды у про; план отдаётся тому, кого пустит арбитр места.
- Итог (16 матчей на карту, ПК 37–43): гранаты старта как у про (Window 0 → 95 %), тушение ×2; гранаты выхода 20 → 24–26 %
  долетают, ответ CT почти нет; `tug` Ancient 24 → 50. Причина — арбитр места: лайнап (уровень 4) перебивают перестановка (6),
  контакт (9), ротация (8); гранаты плана без лайнапа про — физика «не долетит» (В5). Решение о слиянии / следующем шаге — за

## 21.10.2026 — В4 (v394, М138) и след гранаты (v395): лайнап = записанный бросок про; смоки-лайнапы — заплатка «доводка в точку про»
- След гранаты на радаре (v395, владелец 21.10: «что с траекторией») скакал зигзагом: высота рисовалась от пола под каждой точкой —
  над стеной / крышей он резко менялся. Теперь — от плавной линии «пол в месте броска → пол в месте разрыва», высота на рисунке
  плавно до 30 px (смоки с T-спавна идут на ~1300 ед.). Только рисунок; отпечаток — владелец проверит сам.
- Лайнап набора (`lineups.json` → `throws`) — записанные броски про (≥ 3 одинаковых в ≥ 2 демках: место ±6 ед. / с хода ±16,
  поворот / наклон ±0,3°, движение, присед, разбег ±40 ед/с — **проектные** только «с хода» и разбег), до 8 на вариант; сила и прыжок
  на бинде — физикой по разрыву у про (`tools/nades/lineups_rec.py`, `lineups_fit.js`). Записи набора («когда», доля раундов) —
  прежние: меняется только «как кидают». Бот берёт вариант ближе к себе и один из записанных бросков (разброс — как у про), встаёт
  точно, делает записанный разбег (0,4 с — **проектное число**) и кидает этот бросок через тот же `throwNade` (`nadeRecRelease`).
- **ЗАПЛАТКА** (решение владельца 21.10, вариант «а»): смок-лайнап летит по физике, последние 0,3 с (**проектное число**) доводится
  в точку разрыва про и рвётся во время про (`smokePinStep`, 400). Причина: В2б — физика повторяет лайнапы смоков в 24–25 %, полёт
  по ступеням и краям неустойчив. **Снять**, когда физика смоков даст ≥ 60–70 % (`node tools/nades/lineups_fit.js <карта>`).
  Свои смоки (не лайнапы) не трогает.
- Удалено: `BAL.lobErr` и `execErr` для гранат (выдуманный промах), заплатка «с разбега, бот стоит» (`NADE_RUN_V`, поиск «с разбега»
  в `nadeAim`), `nadeSolve` для лайнапов с записью. Записи без строгого лайнапа (у про — «на глаз»: флешки / HE в основном) пока
  кидаются физикой как своя граната — В5.
- Проверка без матчей (записанный бросок → туда же, где у про): флешки 81–89 %, HE 65–70 %, молотовы 46–51 %, смоки по физике
  27–45 % (в игре — 100 % заплаткой). Прогоны ПК 34–36, 16 матчей на карту против v393: гранат −3 / +1 % (Ancient CT / T),
  −2 / −5 % (Mirage) — в пределах 10 %; `nav` Mirage −21 %, `tug` −74 / −46 % (ушло мелькание «пост → лайнап → пост»); остальное
  в шуме. Влито в main. Попутно: подпись версии страницы (`mkpub.py`) — наибольшая версия из последней записи DECISIONS.
