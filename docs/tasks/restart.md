# Начать заново: интерфейс + движок, мозг ботов — с нуля (07.10)

Решение владельца 07.10: логика ботов (решения) удаляется целиком, остаются
интерфейс и движок CS2. Сначала — карта как в настоящей игре, потом новый мозг.
Старая версия — ветка `old-brain-v196` на GitHub (вернуться можно всегда).

## Что остаётся
- **Интерфейс:** радар, табло, панели игроков, киллфид, консоль, отметки (M),
  перемотка и снимки, редакторы карты, публикация страницы.
- **Движок (правила CS2, не решения):** движение по навмешу со скоростями
  оружия, стрельба (С1), урон и броня, бомба/плант/дефуз, таймеры раунда,
  экономика CS2 (награды, бонус за поражения), звуки (шаги, выстрелы, гранаты),
  полёт и действие гранат, видимость (линия взгляда, дым).
- **Данные карты:** стены, навмеш (с высотой z), зоны с названиями, картинка
  радара, лайнапы (как данные).

## Этап 1 — карта (отдельные чаты, по порядку)
Всё проверяется глазами владельца на радаре; одно место на вопрос «кто кого
видит» и одно на «кто кого может прострелить».
1. **Стены и проходы.** Наложить стены на настоящий радар, найти расхождения
   (лишние/пропущенные стены, двери, узкие проходы), показать списком с
   картинками; владелец подтверждает, правим данные.
2. **Высоты и этажи.** У навмеша уже есть высота z. Показать карту высот;
   найти места, где один уровень над другим, крытые места, лестницы и рампы.
   Видимость с учётом уровней (сверху/снизу, через пол не видно).
3. **Высота укрытий.** У каждого ящика/низкой стены — высота: выше головы /
   по грудь (голову видно стоя, присев — нет) / низкая. Видимость считает
   высоту глаз (стоя/присев) и куда видно (голова/тело). Откуда взять высоты —
   решить в начале шага (из геометрии карты, из демок или короткая разметка
   владельцем: ~40–60 объектов на Ancient).
4. **Прострелы.** Какие стены и ящики простреливаются (материал, толщина),
   сколько урона проходит из какого оружия (значения CS2). Значок «прострел»
   в киллфиде начинает работать.
5. **Проверка «кто кого видит».** Клик по точке на радаре — показать, что
   оттуда видно стоя и присев, с учётом этажей, укрытий и дыма; что
   простреливается.

**Редактор карты для владельца (на каждом шаге этапа 1, просьба 07.10).**
Всё, что Claude размечает автоматически, владелец может сам поправить на
радаре: стены и проходы (добавить/сдвинуть/удалить), высоту пола и этажи
(зона → уровень), высоту укрытий (клик по ящику → выше головы / по грудь /
низкий), прострел (клик по стене → простреливается / нет, материал). Один
редактор с вкладками по шагам, галочка «правка карты». Правки сохраняются в
базу страницы (как точки углов раньше) и не пропадают; в начале каждого чата
Claude забирает их в `src/data/`. Отмена последнего действия (Ctrl+Z).

*Сделано (v198): вкладка «стены».* Галочка «правка карты» → панель
(`src/js/19_map_editor.js`): выбор/удаление/сдвиг стены и уголков, новая стена
прямоугольником или многоугольником, Ctrl+Z на несколько шагов, «вернуть как в

«вернуть как в коде» удаляет документ. Новая вкладка (высоты, укрытия,
прострелы) — `mapEdAddTab({...})` в том же файле: свой слой данных и свой
документ в `map`, панель, отмена и сохранение общие.

*Сделано (v199): шаг 2, часть 1 — высоты и этажи, показ и разметка.*
Данные `src/data/heights.json` делает `python3 tools/heights_bake.py --simple-radar
<папка>[,<папка>…] [--report]` (папки — распакованные радары Simple Radar,
`de_ancient_radar.dds/.png`; без `--simple-radar` «крыто» берётся из прошлого
файла; повторный запуск даёт тот же файл; поле `own` сохраняется). У каждого
участка навмеша: высота z, уровень, «крыто сверху» (штриховка Simple Radar),
номер рампы; уступы (перепад > 50 и круче 45°: запрыгнуть / только спрыгнуть /
не пройти), стрелки лестниц и рамп, «уровень над уровнем» — проверено: на
Ancient навмеш нигде не лежит в два уровня (перекрытий в плане нет вообще).
Галочка «высоты» — слой на радаре со шкалой и подсказкой при наведении.
Вкладка «высоты» редактора карты (`src/js/19_map_heights.js`): клик / Shift+клик /
рамка — выделить участки; уровень 0/1/2 (или число), «крыто сверху» да/нет,
«как посчитано автоматически»; клавиши 0–5, К, Esc; отмена общая. Документ
`map/heights` = `{own: [{id, lvl?, cov?}, …], t}` — только правки владельца поверх
heights.json. Картинки — `docs/tasks/img/heights/` (`tools/heights_shot.js`).
Часть 2 (видимость с учётом высот) — после ответа владельца.

**Как Claude забирает правки карты в начале чата.**
1. `ArtifactData` → `get`, артефакт https://claude.ai/artifact/8bpgTJoSqsGTYwjRc8ikDj,
   `collection: "map"`, `doc_id: "walls"`, затем так же `doc_id: "heights"` и `doc_id: "cover"`.
   Документа нет — правок нет, ничего не делать.
2. Ответ (весь JSON документа, обёртка не мешает) сохранить в файл, например
   `/tmp/.../walls_doc.json`.
3. `python3 tools/map_pull.py <файл> --dry` — посмотреть, сколько стен было/стало
   и от какого числа правка; затем без `--dry` — записывает поле `walls` целиком в
   `src/data/walls.json`. Для документа `heights` — то же: скрипт сам видит поле
   `own` и записывает его целиком в поле `own` файла `src/data/heights.json`
   (остальное там не трогает), печатает, у скольких участков правка было → стало.
   Для документа `cover` — то же: поле `own` целиком в поле `own` файла `src/data/cover.json`
   (печатает, сколько правок было → стало, сколько кусков нарисовано). Документы `heights` и
   `cover` скрипт различает по записям (у укрытия id — строка и есть точка pt); если список
   правок пустой — по имени файла (сохранять как `cover_doc.json`) или ключом `--cover`.
4. Пересобрать (`python3 src/build.py`), сказать владельцу, что правка забрана
   (сколько стен / участков с правкой высот / правок укрытий было → стало). Документ в базе не трогать: он совпадает с кодом,
   страница покажет «правка на странице», пока владелец не нажмёт «вернуть как в коде».
